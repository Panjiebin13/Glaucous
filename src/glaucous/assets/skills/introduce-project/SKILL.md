# 介绍项目

目标：基于工作区内的**真实文件**，产出一份简洁、结构化的项目概览，让用户快速理解「这是什么项目、怎么组织、怎么运行、当前状态如何」。

## 步骤

1. **看根目录**：`list_dir` 工作区根目录，先建立整体印象（源码目录、文档、配置文件、版本库）。
2. **读 README**：优先读 `README.md`（如无，找 `README*` 通配的其他变体）；README 通常已含定位、快速开始、文档索引，是最高优先级信息源。
3. **读项目元数据**：按语言识别配置文件并读取——
   - Python：`pyproject.toml`（name/version/dependencies/entry points）、`requirements.txt`
   - Node：`package.json`、`tsconfig.json`
   - Rust：`Cargo.toml`；Go：`go.mod`；Java：`pom.xml` / `build.gradle`
   - 通用：`Dockerfile`、`Makefile`、`.gitignore`（辅助判断技术栈与运行方式）
4. **看主要源码目录**：`list_dir` 源码根（如 `src/`、`app/`、`lib/`），按模块/子包归纳职责；不要逐文件通读，抓目录结构与关键文件即可。
5. **看状态类文件**：存在 `TODO.md` / `CHANGELOG.md` / `docs/` 时扫一眼，提炼当前阶段、里程碑、待办。
6. **汇总输出**，按以下骨架组织（信息缺失的项注明"未找到"而非编造）：
   - 项目定位（一句话）
   - 技术栈 / 依赖要点
   - 目录结构（主要模块职责）
   - 当前状态（里程碑/版本/待办）
   - 如何运行（构建、测试、启动命令）
   - 相关文档索引（如有）

## 约束

- **先读真实文件再下结论**：未读取的文件内容一律不得猜测；不确定就再读，或明确标注。
- **只读探索**：本技能不改动任何文件、不运行构建命令，纯粹产出概览。
- **引用规范**：提及具体内容时用「文件路径:行号」格式，方便用户定位。
- **风格**：简体中文，简洁直接，先结论后依据。

## 验收标准

- 能回答：这是什么项目、主要目录/模块怎么分工、用什么技术栈、当前处于什么阶段、如何运行和测试。
- 概览中每一条关键信息都能追溯到真实文件。
- 全程零修改：git status 不应因本次介绍产生任何变更。
