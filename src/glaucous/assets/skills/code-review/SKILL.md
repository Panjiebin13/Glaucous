# 代码评审清单

按以下顺序逐项核查本次改动，发现问题先引用「文件路径:行号」再给结论：

1. **范围**：改动是否只覆盖任务要求，无夹带重构/无关变更。
2. **正确性**：主路径逻辑是否与需求一致；用 read_file 核对被改函数的调用方。
3. **边界**：空输入、越界序号、缺失文件、非法参数是否有明确处理。
4. **错误处理**：异常是否被吞掉；失败路径是否给用户可行动的提示。
5. **一致性**：命名、注释密度、错误文案风格是否与相邻代码一致。
6. **回归**：既有测试是否需要更新；新增逻辑是否留下测试债务说明。

输出格式：先给结论（通过 / 有 N 处需修改），再按 严重→轻微 列出问题清单。
