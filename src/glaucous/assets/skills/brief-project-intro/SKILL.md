# 简略介绍项目

目标：基于工作区**真实文件**，快速产出一份精简的项目速览（3~5 条要点），让用户 30 秒内抓住项目全貌。信息不足时如实标注，不编造。

## 步骤

1. **看根目录**：`list_dir` 工作区根目录，一眼确认源码目录、文档、配置文件。
2. **扫关键文件**：读 `README.md`（或 README 变体）首段 + `pyproject.toml` / `package.json` 等元数据，提取：项目定位一句话、技术栈、入口/运行方式。
3. **看当前状态**：如存在 TODO.md / CHANGELOG.md 或 git 分支信息，扫一眼提炼当前阶段与未竟事项。
4. **汇总输出**，固定骨架（每条一行，信息缺失注明"未找到"）：
   - 定位（一句话）
   - 技术栈 / 依赖要点
   - 主要模块（1~3 个核心目录及其职责）
   - 当前状态（里程碑/版本/待办）
   - 如何运行（启动命令）

## 约束

- **先读真实文件再下结论**：未读取的内容不得猜测；时间紧可只读 README 首段 + 元数据，但引用时用「文件路径:行号」标注依据。
- **只读探索**：不改动任何文件、不运行构建命令。
- **精简优先**：控制在 15 行以内；想深入了解时建议改用 introduce-project 技能。
- **风格**：简体中文，先结论后依据，直接给要点列表。

## 验收标准

- 5 条骨架全部有真实文件支撑，可追溯；
- 输出不超过 15 行，无需打开任何文件即可理解项目全貌；
- 全程零修改：git status 不因本次介绍产生变更。
