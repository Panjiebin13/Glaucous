## 阻塞事项（必须修复）

- **[B-01] L0 截断在「字节超限但行数不足头尾之和」场景下完全失效，超大正文原样入史** — 位置：`src/glaucous/safety/output_limit.py:48-54`（else 分支）— 依据：spec §4.5「截断形态：头 200 行 + 省略标记 + 尾 50 行」、FR-24「工具输出截断……截断不丢数据」、概设 §4.2 L0（>300 行 **或** >50KB 触发的目的即将入史正文压至有限规模）— 触发条件：工具输出 ≤300 行（不触发行阈值）但 UTF-8 字节 >50KB（字节阈值触发），典型如压缩 JSON、minified JS、base64 单行块 — 实测证据：2 行 × 30KB → 截断后正文 60099 字符（**大于原 60001**）；260 行 × 300B（78259 字节）→ 截断后仍 75348 字符（超 50KB 阈值 47%）— 后果：L0 形同虚设，数 MB 级正文入史推高 token 估算、可能连锁误触发 L1/L2，回取提示指向的落盘文件与截断后正文几乎等长、read_output 分段回取失去意义；`omitted=0` 时还输出「中间 0 行已截断」的矛盾标记 — 修复建议：else 分支对保留行追加字符级二次截断（如每行截 500 字符后再拼装），或对 head 部分按字节硬截断并附「已按字节截断」标记；同时 omitted=0 时省略省略标记行。

- **[B-02] L2 失败计数缺少「占用降回阈值以下时清零」分支，非连续失败会被误判为连续并提前终止** — 位置：`src/glaucous/agent/loop.py:178-184`（`_enforce_budget` 中 low 早退与非 critical 早退两个 return 路径均未重置 `self._l2_failures`）— 依据：spec §4.7 S-01「压缩成功**或占用降回阈值以下**时失败计数清零」、D12「连续失败 2 次后走终止③」的「连续」语义 — 触发条件：L2 失败 1 次（计数 1）→ 后续轮次 L1 加深裁剪生效、占用降回 warn/low（早退未清零）→ 数轮后再次进入 critical 且 L2 失败 1 次 → 计数累积至 2 → 直接走预算耗尽终止③ — 后果：本应获得重试空间的会话被提前优雅终止（可 resume 但违背 spec 定义的行为）— 修复建议：在 `report.level != "critical"` 的早退分支（或 low 分支）加入 `self._l2_failures = 0`（单行修复）。

## 建议（建议修复 / 可选优化）

- **[S-01] ask_user 的 options 对非字符串元素做了 str() 转换保留而非过滤** — 位置：`src/glaucous/tools/interactive.py:59` — 依据：spec §4.3「非字符串元素过滤、超 6 个取前 6 个」— 差异：模型传 `[123, {"x":1}]` 时 spec 语义应过滤为 `[]`，实现得到 `["123", "{'x': 1}"]`（dict 候选展示难看但无害）— 建议：改为 `[opt for opt in (options or []) if isinstance(opt, str) and opt.strip()]`；或认可「简单类型宽容转换」语义并回写 spec 表述。
- **[S-02] trim_history 的「轮」口径与 spec S-13 存在偏差** — 位置：`src/glaucous/context/compactor.py:66-79` — 依据：spec §3/S-13 轮定义包含「无 tool_calls 的 assistant（终答）单独成轮」，§4.6 豁免「最近 KEEP_RECENT_ROUNDS=2 轮」— 差异：实现豁免的是「最近 2 个**含 tool 结果**的轮」，当最近序列含终答轮时豁免窗口比 spec 偏大（如 [tool轮A, tool轮B, 终答轮] 场景，spec 应裁 A，实现不裁）— 方向保守（多保留少裁剪）、无正确性风险 — 建议：统一口径，或修订 spec 表述声明「豁免按含 tool 轮计」。
- **[S-03] `_extract_goal` 在 planning 与 compactor 双份实现，且 `lstrip("目标：: ")` 字符集剥离会误伤正文** — 位置：`src/glaucous/tools/planning.py:46-55` 与 `src/glaucous/context/compactor.py:102-112` — 依据：spec S-15 要求两处「同规则」— 风险：双副本未来漂移；`lstrip` 按字符集剥离，目标正文以「目标」开头时（如「目标检测是……」）会被误剥成「检测是……」— 建议：提取为单一共享函数（如放 extensions 或 context 公共模块），改用 `re.sub(r"^[#*\s]*目标[：:]?\s*", "", line)` 一类正则前缀剥离。
- **[S-04] 规则超长提示紧贴正文、无分隔** — 位置：`src/glaucous/extensions/rules.py:41-42`（`f"{text.rstrip()}{note}"`）— 依据：spec §4.1「超 4000 字符时在该段尾部附提示」（拼接形态未规定）— 现状：文件末尾无换行时提示与正文最后一行粘连，可读性差 — 建议：`f"{text.rstrip()}\n\n{note}"`。
- **[S-05] tool_end 的 UI 行数摘要基于截断后正文，metadata.lines 原始记账未被 UI 消费** — 位置：`src/glaucous/cli.py:250-260`（`result.content.splitlines()`），对照 `src/glaucous/agent/loop.py:157-168` 与 `src/glaucous/tools/base.py:259-268`（lines 按原始行数记账）— 依据：spec §4.5 挂接点段「工具行 UI 摘要不受影响」的本意是原始行数可见；但同节「事件一致性」段又允许 UI 与入史一致（现实现符合后者）——spec 两处表述本身有张力 — 建议：render_event 的 tool_end 优先展示 `metadata.lines`（如「共 5000 行（已截断至 256 行）」），并随实现一并对齐 spec 表述。
- **[S-06] TODO.md 任务 2.1 的项目规则路径描述与实现/spec 不符** — 位置：`TODO.md:50`（「项目 .glaucous/glaucous.md」）— 依据：spec §4.1 与实现均为 `<workspace>/glaucous.md`（项目根目录），实现正确、文档笔误 — 建议：修正 TODO.md 表述，避免验收时按错误路径检查。
- **[S-07] render_event 的 state 形参未使用** — 位置：`src/glaucous/cli.py:225` — 现状：签名带 `state: SessionState` 但函数体未消费 — 建议：删除形参或补注释说明为 M3 rich 状态栏预留，避免误导调用方。
