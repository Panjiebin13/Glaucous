## 二、阻塞问题

### B1. F4 落账判定不完备：自然终止分支的 budget/mode_changed 事件紧随最终回答正文发射，按现行判定规则最终回答必被误落账为思考过程条目
- **维度**：结构与可执行性（内部自洽）× 概设一致性（loop 事件契约时序）
- **spec 位置**：§4.2「**落账判定（loop 零改动，无新事件）**：当前段正文缓冲在「下一个非 text 事件到达」时落账为思考过程条目（标记为正文段），**因为中间步正文之后必有 tool_start 等事件紧随**；`run()` 返回后（finally）当前段缓冲即最终回答（loop 语义：最后一步响应正文为最终回答），**不落账**为思考过程，而是输出呈现」；§4.4 步骤 2「最终回答呈现：当前段正文缓冲非空且本轮无异常 → 打印缓冲全文」；§4.1「唯一例外是**最后一步响应的正文 = 最终回答**」
- **上游位置（代码事实 + 本批测试声明）**：`agent/loop.py` L101~110 自然终止分支——`if not msg.tool_calls:` → `push_assistant(msg)` → **`self._emit_budget()`** → Build 下 `return_to_plan()` → **`self._emit("mode_changed", ...)`**：最终回答的 text 流（L98 `on_text=self._emit_text`）之后、`run()` 返回之前，固定发射 budget 与 mode_changed 两个非 text 事件。本批 §五亦声明将断言「中间步落账、**最终回答不落账**」
- **冲突说明**：落账触发器是「下一个非 text 事件到达」，而自然终止（最常见路径）中最终回答正文之后同样有非 text 事件（budget、mode_changed）紧随——按字面规则，最终回答正文会在 budget 事件到达时被落账为思考过程条目，随后 §4.2「run() 返回后当前段缓冲即最终回答」读到空缓冲，§4.4 步骤 2 的正文打印落空；若实现改为落账不清缓冲，则最终回答同时进思考缓冲（/expand 重放它），直接违反 §4.1「唯一例外」。判定所依赖的理由句「中间步正文之后必有 tool_start 等事件紧随」对最终回答不成立（轮末哨兵事件未排除），四个条款（§4.1/§4.2/§4.4 步骤 2/§五测试断言）在自然终止路径不能同时成立。用户决策 ①「最终回答流结束后从缓冲一次性完整显示」在主路径不可实现，属 F4 核心交付缺陷
- **修复方向**：将落账触发器限定为「任务继续类事件」（tool_start/compressed 等），或显式列出轮末哨兵事件（budget/diagnostic/mode_changed）不触发落账、由 finally 依「本轮是否已出现哨兵事件」分辨当前段缓冲归属；同步修订 §4.2 理由句表述，并使 §五「最终回答不落账」断言在自然终止场景可验收

### B2. F4 重置语义收窄未贯穿：§3.2（F3）的消费时序引用旧 `reset_turn_buffers`（轮首清空缓冲）与 §4.3「下一轮任务开始不再清空」直接冲突，且 turn_usage 的轮级清零时机在新方案下全文未定义
- **维度**：结构与可执行性（内部自洽、F3×F4 衔接）
- **spec 位置**：§3.2「cli.py repl：handle_command 返回后检查 ctx.pending_task 非空 → 消费（置 None）并**走完整任务轮流程**（**reset_turn_buffers → thinking start → run(task)** → 轮末渲染，**与本轮新 F4 时序一致**），随后回到输入循环」；§4.3「**重置点收窄**：仅 /clear 与 /resume 重置会话缓冲；**下一轮任务开始不再清空**（推翻前批 r4-B2 的「轮首重置」……）」；§4.3 仅定义「折叠摘要行 N 口径：轮开始清零计数器」，未提 turn_usage
- **上游位置（代码事实 + 前批 spec）**：`commands.py` L130~137——`reset_turn_buffers(ctx)` 现状语义为 `ctx.turn_events.clear()` + `turn_usage` 四字段归零，docstring「调用时机：repl 拿到非斜杠输入、调 run() 之前；/clear、/resume 也显式调用」；`cli.py` L1264~1266 任务轮轮首调用之。前批 §3.3「缓冲重置时机（r4-B2）：每轮任务开始时……调 commands.reset_turn_buffers(ctx) 清空上一轮缓冲」；前批 §5.2 确立 turn_usage「本轮累计」口径（r2-S2 修复）
- **冲突说明**：二读皆矛盾——① 若 /skill 消费轮照 §3.2 调用现状语义的 `reset_turn_buffers`，会话级思考缓冲在 /skill 轮首被清空，违反 §4.3「下一轮任务开始不再清空」（用户刚可 /expand 回看的全会话思考被 /skill 一轮抹掉）；② 若照 §4.3 执行（轮首不清缓冲），§3.2 的「reset_turn_buffers →」步骤不存在，该步骤清单错误。此外 §4.3 的「重置点收窄」字面只谈「会话缓冲」，`turn_usage`（用量行与折叠行 token 段的唯一数据源）是否仍轮首清零全文未定义：若随缓冲一并「不再清空」，用量行将跨轮累加，破坏前批 R5「本轮累计」口径；§五修订清单亦未包含 usage 口径用例。实现者无法据现行文本写出正确轮首动作
- **修复方向**：在 §4.3 显式重定义轮首动作清单——清零轮级 N 计数器 + turn_usage 归零、会话缓冲不清；统一 §3.2 表述（将「reset_turn_buffers」改为新语义的函数名或动作清单），全文同步前批 R5 口径表述，并在 §五补 turn_usage 轮级归零断言

### B3. 异常路径下当前段缓冲正文的归属未定义：只定义「不呈现」，与 §4.1「/expand 重放全会话思考过程（含中间步正文）」的承诺存在静默缺口
- **维度**：结构与可执行性（内容完备、内部自洽）
- **spec 位置**：§4.4 步骤 4「异常路径：收缩与用量行照常，跳过步骤 2 的正文与卡片（**缓冲正文可能是中间步残留，不呈现**）」；§4.1「/expand 的作用域为**整个会话**：重放自会话开始（或 /clear、/resume 重置点）以来全部思考过程（**含中间步正文**、工具调用与结果、交互伪事件），按时间序逐条渲染」
- **上游位置（代码事实）**：`cli.py` L1277~1284——异常路径为 `except (KeyboardInterrupt, asyncio.CancelledError)`（Ctrl+C/取消，含「已中断本轮」提示）与 `except Exception`（LLMError 等兜底「本轮执行失败」），finally 照常执行；异常发生时「当前段正文缓冲」中极可能残留中间步正文（其后尚未到达任何非 text 事件，落账未发生——例如 text 增量与 Ctrl+C 之间无其他事件）
- **冲突说明**：§4.4 步骤 4 只定义了「不呈现」，未定义该残留正文是否落账进会话缓冲：若不落账，异常轮的中间步正文永久丢失，§4.1 的全会话重放承诺对异常轮静默落空（未声明裁剪）；若落账，finally 需新增落账动作（spec 未写，且 §五修订清单的落账时序用例未含异常分支）。两读均缺口，影响 /expand 功能验收与 finally 实现结构。存疑，提请作者确认
- **修复方向**：二选一并显式写入 §4.4 步骤 4——① 异常分支将当前段缓冲显式落账为思考正文段（保留 /expand 回看，推荐）；② 声明「异常轮残留正文丢弃」为显式裁剪并登记理由/偿还去向；§五同步补异常分支落账断言

### B4. diagnostic（终止诊断）事件在 F4 新分流中的呈现归属未定义，与 loop→CLI「必达」事件契约冲突；_terminate 轮的 md 卡片行为存在条件歧义
- **维度**：概设一致性（接口契约）× 结构与可执行性
- **spec 位置**：§4.2「text 增量不再直接打印：一律 append 进动态区滚动行（**与 非 text 事件共用 8 行滚动窗口**）」（修订前批 §3.1，沿袭「非 text 事件不逐条直接打印、进 Live 动态区」条款，列举为「tool_start/tool_end/budget/compressed/模式切换**等**」）；§4.3 会话缓冲条目①「非 text 事件」；§4.4 步骤 2 触发条件「当前段正文缓冲**非空**且本轮无异常 → 打印缓冲全文……随后渲染 🕊 md 卡片」
- **上游位置（代码契约）**：`agent/loop.py` L41「事件类型：text（流式正文）/ tool_start / tool_end / **diagnostic（终止诊断，必达）** / mode_changed……」；L246~255 `_terminate` docstring「终止路径的统一交付：诊断文本经事件通道显式通知（不依赖返回值推断）……CLI 无法区分『自然终答已流式交付』与『诊断未交付』；**diagnostic 事件保证必达**」（步数上限/解析熔断路径的诊断文本唯一交付通道）；`cli.py` L511~513 render_event diagnostic 分支注释「保证多步轮中必达」；前批 R7——md 卡片文本来源为 `run()` 返回值（_terminate 路径返回 diagnostic 文本）
- **冲突说明**：diagnostic 属非 text 事件，按 §4.2/§4.3 字面将进动态区滚动行并记录会话缓冲；多工具轮中滚动窗口（8 行）必然滚出诊断文本，轮末收缩为一行折叠摘要后**熔断原因对用户不可见**——破坏「必达」契约，且 F4 未声明对该契约的任何偏离（静默偏离）。若改读为「diagnostic 保持直打」，则与前批沿袭的「非 text 事件不逐条直接打印」条款冲突，spec 未写明例外。另：_terminate 轮（无异常、当前段缓冲已随 diagnostic 事件落账/或为空、run() 返回值 = diagnostic 文本）下 §4.4 步骤 2 的「缓冲非空」条件不成立，md 卡片是否渲染（前批口径：按返回值渲染）歧义，诊断的轮末呈现路径整体悬空。存疑，提请作者确认
- **修复方向**：在 §4.2 显式列出 diagnostic 的分流例外（建议：保持直打/或轮末必现呈现一行），声明其不受「非 text 进滚动区」约束与「必达」契约的对应关系；在 §4.4 步骤 2 补充 _terminate 轮（缓冲空、返回值非空）的呈现定义（卡片渲染与否、诊断以何种形态必现）

## 三、建议问题

### S1. F1 两段式 Enter 与 Escape 的 complete_state 生命周期衔接未定义（prompt_toolkit 约束下存在条款冲突）
- **维度**：结构与可执行性（技术描述歧义）
- **位置与摘录**：§1.2「自定义 key_bindings 覆盖 PromptSession 默认 Enter 行为：`buffer.complete_state` 存在且有候选 → `apply_completion()`；否则 `accept()`。**Escape 仍可关闭菜单（随后 Enter 直接执行，等同跳过补全）**」；§1.1「before_render 钩子或等价机制：检测 `buffer.complete_state` 非空且 `complete_index is None` 时调 `complete_next()`」
- **建议**：prompt_toolkit 默认 emacs 绑定下 Escape 为 meta 前缀，不保证存在「关闭补全」默认绑定；若需本批新增 escape 绑定，必须显式清空 complete_state，否则 Escape 后 §1.2 的判定条件（state 存在且有候选）仍为真 → Enter 仍走 apply_completion，与「随后 Enter 直接执行」矛盾；且 state 残留时 §1.1 的 before_render 逻辑会因 `complete_index is None` 重新调 `complete_next()` 使菜单/选中态复活。建议补一条「Escape 绑定 = cancel_completion（complete_state 置空）」及 apply_completion 后 state 生命周期的定义；其余（key_bindings 覆盖 Enter、before_render 默认选中、complete_while_typing 交互）技术描述明确可落地

### S3. 折叠行 N 口径构成未列全 + 空段（无 text 响应）落账规则缺失（r4-B1 同型风险）
- **维度**：结构与可执行性（口径完备）
