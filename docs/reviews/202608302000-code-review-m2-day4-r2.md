## 建议（建议修复 / 可选优化，均非阻塞）

- **[S-01] `omitted=0` 时仍输出「中间 0 行已截断」矛盾标记** — 位置：`src/glaucous/safety/output_limit.py:53-57` — 依据：r1 B-01 后果段曾指出该观感问题；本轮所选字节兜底方案未覆盖此项 — 现状：行数 ≤200 且字节超限时（实测 2 行×30KB 场景），标记行内容为「中间 0 行已截断」，且该标记位于全部保留行之后、语义为纯噪声 — 建议：`omitted == 0` 时跳过标记行，或在该分支改输出「输出超长，已按字节截断」类准确描述。
- **[S-02] 字节兜底后叠加回取提示行，最终入史总字节略超 50KB** — 位置：`src/glaucous/safety/output_limit.py:69-71` — 实测：60KB 场景最终入史 51322 字节（正文 51200 + 提示行 ~122B）— 依据：spec §4.5 截断形态本就定义「……+ 一行回取提示」，正文 ≤50KB + 提示行符合 spec 语义，故不阻塞 — 可选优化：若希望整体严格 ≤50KB，可在截断预算中预留 `len(saved_note.encode()) + 1` 字节。
- **[S-03] 落盘失败且触发字节兜底的组合场景下提示文案轻微失准** — 位置：`src/glaucous/safety/output_limit.py:64` — 现状：`saved=False` 时提示为「仅保留以上头尾部分」，但字节兜底后实际保留量可能少于头尾 — 触发条件：写入失败（OSError）与超限同时发生，属罕见组合 — 建议：该分支文案并入「超长部分已丢弃」表述，或保持现状（可接受）。
