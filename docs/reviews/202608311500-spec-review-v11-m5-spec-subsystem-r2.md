## 三、建议问题

### S1. 决策 2 否决「免费获得」方案的理由句「时序在 push_user 后」与代码事实不符

- **维度**：结构与可执行性（内部自洽 / 与既有代码相容性）
- **位置与摘录**：决策 2「**不采用**『仅靠 loop 入口接线免费获得』方案：其时序为 **push_user 之后**，不严格满足『该任务前』，且 mock 回放下不可观测」；实际代码 `agent/loop.py` L86-107：`run()` 入口先创建 checkpoint（注释明言「**每轮入口快照（push_user 之前取锚与计数）**」，L87），其后才是 `self._history.push_user(task)`（L107）。
- **建议**：M4 入口快照与显式权威快照同为「任务动作前」，真正差异在**测试可观测性（全 fake 回放中 loop 内部快照不可计数）、任务标签可精确标注、概设 §7.4『每任务开始前打任务级 checkpoint』字面对齐**三点——建议将理由句中的时序表述更正为上述口径。此误差不影响实现判断（双保险口径已唯一确定），故不升级为阻塞。

### S2. 「工程结构增补：spec/ 包」的概设引用号仍错指 §10（应为 §11）——r1-S1/S3 残留

- **维度**：概设一致性（引用正确性）
- **位置与摘录**：
  - spec 头部「§10（**工程结构增补：spec/ 包**）」；
  - 决策 15「概设 **§10 模块清单**写 `spec/tools.py`」；
  - 概设 v1.1 实际结构：**§10 = 配置与安全增补**（L305-322，config.toml 样例）；**§11 = 工程结构增补**（L326-350，`spec/` 包含 `store.py / templates.py / pipeline.py / tools.py  # read_spec 工具 + Spec 锚注入`）。
