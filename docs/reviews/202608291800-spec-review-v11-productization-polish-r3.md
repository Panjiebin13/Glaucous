## 三、新增阻塞问题

### r3-B1. 「N 步」新口径（非 text 事件条数）与 §3.4 不变量「N 与 /expand 打印条数一致」不可同时成立
- **维度**：结构与可执行性（内部自洽；r2-B1 修复的波及面）
- **spec 位置**：
  - §3.1「⚙ 思考中 · N 步」；「**N = turn_events 中非 text 事件条数，text 增量不计步**」
  - §3.2「`turn_events`……记录两类条目：① on_event 的 `(event, payload)` **全量**；② 交互伪事件」
  - §3.1「**/expand**：打印当前缓冲的**全部**事件（复用 `render_event` 逐条渲染……）」
  - §3.4 不变量「**摘要行的 N 与 /expand 打印条数一致**」
- **上游位置（上轮评审依据）**：r2-B1 修复方向原文「同步定义「N 步」计数来源与 `turn_events` 收录范围，**使 §3.4 不变量可验收**」（r2 报告 §三）
- **冲突说明**：缓冲按 §3.2 收录 on_event 全量（含 text 增量）与伪事件，/expand 按 §3.1 打印「全部」缓冲条目，而 N 只计非 text 条数。任何含 text 事件的轮次（几乎全部轮次，含纯问答轮）必有：/expand 打印条数 = N +（text 增量条数）+ … > N，不变量恒不成立。§3.1/§3.2/§十.3 三处口径已互相对齐，唯 §3.4 字面未同步——实现者与测试编写者无法同时满足两条条款，验收标准不可判定。
- **修复方向**：存疑，提请作者确认。二选一（或等价方案）：① 修订 §3.4 不变量措辞为与口径一致的形式（如「摘要行的 N 与 /expand 输出中非 text（步骤类）条目数一致」）；② 为 /expand 的输出范围或计数另作定义并同步 §十.3 断言。同时建议 §十.3 增补一条针对该不变量的断言声明，使验收可测。

## 四、新增建议问题

### r3-S1. stream_end 事件锚定表述残留（§7 / §九）与异常轮用量行措辞（§3.3）
- **维度**：结构与可执行性（术语与表述统一）
- **位置与摘录**：§7「流式期间保持逐字保真（现状不变）；**`stream_end` 处理后**追加渲染完整回答为 Markdown 卡片」；§九表 R7 行「render_answer_card + **stream_end 接线**」；§3.3「异常时跳过步骤 2/3……**用量行仍按已收集数据打印**」；对照 §3.1「stream_end 事件仅作为折叠区内容定格的信号」、§5.3「供应商不返回 usage → 整轮无 usage 行」
- **建议**：时序上不构成矛盾（stream_end 于 `return` 前发射，「其后」与「run() 返回后」兼容），但 r2-S1 修复已将渲染锚点统一为轮末，§7/§九 残留的事件锚定表述与 §3.3 异常轮用量行是否遵循 §5.3 抑制规则未点明，易使实现者误读。建议统一为轮末锚定表述，并在 §3.3 注明异常轮用量行沿用 §5.3 口径（无数据则不打印）。

### r3-S2. TTY 下最终回答三重呈现（Live 内流式 + 轮末全文重述 + md 卡片），与用户决策仅承诺「追加卡片」存在体验落差
- **维度**：结构与可执行性（用户决策符合性，非矛盾）
- **位置与摘录**：§3.1 步骤 2「打印完整最终回答全文（取 `run()` 返回值，一次性输出——……轮末全文重述保证与管道模式输出对齐）」、步骤 3「按序执行 R7（md 卡片）」；头部决策记录「md 渲染为流式结束后追加卡片」
- **建议**：决策记录只承诺「追加卡片」，全文重述是折叠机制的配套新增并附显式理由（Live 为 8 行滚动窗，长回答会被滚出；管道模式全量输出），属有意设计、非静默偏离；但 TTY 用户将看到同一回答「Live 内逐字 → 轮末原文全文 → md 卡片」三次呈现，而管道模式仅一次。建议提请用户确认是否保留原文全文重述（可选方向：仅在回答曾滚出 Live 窗口时重述、或省略重述仅保留 md 卡片、或重述与卡片二选一），确认结果落决策记录行。
