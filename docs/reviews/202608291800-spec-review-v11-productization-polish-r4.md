## 三、新增阻塞问题

### r4-B1. §3.1 的 N 定义（仅非 text 事件）与 §3.4 不变量的统一口径（非 text + 交互伪事件）在含交互轮次不能同时成立
- **维度**：结构与可执行性（内部自洽；r3-B1 修复的波及面，同形残留）
- **spec 位置**：
  - §3.1「顶行计数『⚙ 思考中 · N 步』；**N = 已收纳的非 text 事件条数**」
  - §3.2「记录两类条目：① 非 text 的 on_event 事件 `(event, payload)`（text 增量不缓冲，**与思考区收纳范围一致**）；② 交互伪事件 …（回调内部记录，供 /expand 完整回看本轮人机交互）」——§3.2 自身界定思考区收纳范围 = 仅类别①
  - §3.4「摘要行的 N 与 /expand 打印条数一致（两者同为「非 text 事件 + 交互伪事件」口径）」
  - §十.3「摘要行 N 与 /expand 条数一致性」
- **上游位置（上轮评审依据 + 代码事实）**：r3-B1 修复方向原文「修订 §3.4 不变量措辞为与口径一致的形式……使『N 步』口径与不变量**可同时验收**」（r3 报告 §三）；代码事实：Build 逐次审批下每次工具派发经 `make_decision_callback` 阻塞询问（cli 四个阻塞点之一，§3.2 自行列明），审批轮必产生类别②条目——r1 报告 B4 即认定「审批与求助恰是本轮交互的主路径」
- **冲突说明**：按 §3.1/§3.2，N 与 Live 思考区收纳均只计类别①；按 §3.4/§十.3，N 须与 /expand 打印条数（类别①+②）一致。任何含审批/提问交互的轮次（Build 逐次审批的常规多工具轮必有）均有 /expand 条数 = N + 伪事件条数 > N，两条款不可同时满足——实现者无法判定摘要行与顶行的 N 该按哪个口径计数，§十.3 一致性断言随之不可验收。与 r3-B1 同形：三处已对齐、一处（§3.1 N 定义）未同步。
- **修复方向**：存疑，提请作者确认。二选一（或等价方案）：① 若 N 意在覆盖交互伪事件，将 §3.1 的 N 定义同步为 `turn_events` 条目数（含伪事件），Live 顶行计数语义一并说明（伪事件在 pause 期间记录、resume 后计数更新的形态）；② 若 N 只计步骤类事件，将 §3.4 不变量改为「摘要行的 N 与 /expand 输出中非 text 事件条目数一致」并同步 §十.3 断言措辞。

### r4-B2. §3.1 步骤 3 于轮末清空 `turn_events`，而 /expand 只可能在轮末之后被调用——「回看」永久为空，与五处条款直接冲突
- **维度**：结构与可执行性（内部自洽；R3 核心功能不可执行）
- **spec 位置**：
  - §3.1 步骤 3「清空 `ctx.turn_events` 与 `ctx.turn_usage`（调用 `commands.reset_turn_buffers(ctx)`）」；/expand「打印当前缓冲的全部条目……缓冲为空提示『本轮暂无可展开的思考过程』」；摘要行「💭 思考过程（N 步 · ↑Xk ↓Yk tokens）**— /expand 查看**」
  - §3.2②「交互伪事件……供 /expand 完整回看本轮人机交互」
  - §3.3「非 TTY（管道/重定向）……turn_events 仍记录（**管道下 /expand 可用**）」；异常路径「缓冲清理总是执行」
  - §十.3「`reset_turn_buffers` 清理时机……摘要行 N 与 /expand 条数一致性」
  - §十一.3「思考区动态滚动 → 回答后收缩为摘要行 → **`/expand` 回看（含交互记录）**」
  - 头部决策记录「思考折叠用 /expand 展开」；§〇「R3 思考过程折叠 + /expand 展开」
- **上游位置（历轮评审依据 + 代码事实）**：r1~r3 一致将 /expand 回看作为 R3 验收内容（r2-S2「在 `reset_turn_buffers` 的清空时机上保持一致」即提示过该耦合）；代码事实：repl 为单线程输入循环（cli.py `while True` 输入分派，`await ctx.loop.run(task)` 期间用户输入被阻塞），/expand 作为斜杠命令只能在轮末 `finally`（步骤 1~3）执行完毕之后分派——此刻缓冲已被步骤 3 清空
- **冲突说明**：按现行文字，任何路径（正常轮、异常轮、管道）下 /expand 被调用时 `turn_events` 恒为空，永远返回「本轮暂无可展开的思考过程」；摘要行提示「— /expand 查看」与 §十一.3 验收不可达，R3「折叠 + 回看」的用户决策价值落空；§十.3 的一致性断言在真实流程中也无非空缓冲可依（仅能手搓缓冲绕过轮序验证）。该矛盾自 v1.0（「每轮结束……清空」，见 r1 报告 S3 引文）即存在，历轮未检出，本轮按任务全文快扫发现。旁证：§3.3 的 /clear、/resume 显式清空条款（S3 修复）只有在缓冲可跨轮存活时才必要，与步骤 3 的轮末清空互相印证矛盾。
- **修复方向**：存疑，提请作者确认。方向（二选一或等价）：① 将 `turn_events`（及/或 `turn_usage`）清空时机移至**下一轮任务开始处**（`run()` 调用前置空），轮末 `finally` 不再清空，使 /expand 在轮间可回看上一轮——需同步修订 §3.1 步骤 3、§3.3（/clear、/resume 条款语义随之变化）、§十.3「清理时机」断言与 §5.2 口径表述（用量行渲染先于清空的关系不变）；② 保留轮末清空但为 /expand 单列「上一轮快照」缓冲，并在 §3.1/§十.3/§十一 声明其生命周期。无论取哪种，摘要行「— /expand 查看」提示须与实际可用性一致。
