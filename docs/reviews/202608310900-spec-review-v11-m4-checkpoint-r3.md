## 二、阻塞问题

### B6. §3.3 空历史哨兵分支的「（no-op）」括注与规范截断流程、决策 3、概设 §5.1 语义冲突：回退到空历史首轮 checkpoint 时「清空对话」与「什么都不做」两种相反行为并存且无法消歧（B4 修复补文引入）

- **维度**：结构与可执行性（文档内部矛盾影响实现判断）＋ 需求一致性（FR-42「任意 checkpoint」达成缺口风险）
- **spec 位置**：
  - §3.3 L124（本轮 B4 修复新增的分句）：「……绝不静默 no-op 或错位截断；**`anchor_digest == ""` 为空历史首轮哨兵（B4），仅当 `count == 0` 时合法（no-op）**」
  - 同节规范流程 L125：「校验通过 → **内存截断 + JSONL 重写**（首行 meta 不动，其余行重写为截断后消息）」
  - 决策 3 L13：「**回退到更早的 checkpoint 即截断更多轮次——单一机制覆盖任意深度**」
  - 佐证贯通面：§四 L161-166 空历史首轮实际创建的 checkpoint 即为 `(message_count=0, anchor_digest="")`，经 §3.4 L134 进入 `truncate_to(0, "")` 的调用路径真实可达
- **上游位置**：
  - 概设 §5.1 L147-148：「默认保留对话上下文；**「同时回退上下文」= 截断 History 至该 checkpoint 对应轮次前**（JSONL 同步截断，配对校验复用 load 的修复逻辑）」——空历史首轮 checkpoint「对应轮次前」= 0 条消息，即截断到 0 = 清空对话，是真实截断操作
  - 需求 §2.2 FR-42 L70：「/rollback **可回退到保留期内任意 checkpoint**；默认只回退文件、保留对话上下文；提供"同时回退上下文"选项」——「任意」含空历史首轮创建的 checkpoint
  - 需求 §4 裁剪底线 L139：「裁剪底线（不可裁剪项）：……**checkpoint 回退**……」
- **冲突说明**：空历史首轮 checkpoint 的 `(count=0, anchor="")` 配对经 §3.4 上下文二问真实进入 `truncate_to(0, "")`，此时当前历史非空（≥1 个已完成轮次，否则 /rollback 无从触发该 checkpoint 的回退流程），概设 §5.1 定义的语义是「截断至该轮次前」= 清空对话。但 §3.3 括注「（no-op）」按本节自身词汇（同句前半「绝不静默 **no-op** 或错位截断」中 no-op 即指「操作不做任何事」）只能读作「该配对下操作不做任何事」，与 L125 规范流程（count=0 → 其余行重写为 0 条消息 = 清空）、决策 3「单一机制覆盖任意深度」、概设 §5.1 直接冲突。两种读法行为相反：①若实现者按字面实现 `count == 0` 提前返回，最早 checkpoint 的上下文回退**静默失效**——恰违反本 spec「绝不静默 no-op」的一贯立场，FR-42「任意 checkpoint」与决策 3「任意深度」在该场景落空（触及裁剪底线「checkpoint 回退」的实际达成）；②若读作「锚校验环节为空操作」（count=0 时无消息可哈希、校验自然空过），则仅是冗余括注。**文档无法消歧哪一种是作者本意**，实现判断被实质影响；且 §七 用例 7 仅测 mid 截断与锚不匹配、用例 9 仅测创建侧，count=0 截断路径无任何断言兜底，误实现不会被测试捕获。r2 报告对该分支的修复方向原文为「空历史 ↔ 空锚为合法配对，**truncate 到 0 = 清空对话**」——spec 落笔为「（no-op）」，与既定修复语义相反。级别判定存疑（仁慈读法下可降为建议），按「存疑时升级为阻塞」规则定为阻塞，**存疑，提请作者确认**：请作者确认本意是「锚校验环节空操作」还是「整个截断操作为 no-op」。
- **修复方向**：将「（no-op）」改为明确截断语义的表述（如「仅当 `count == 0` 时合法；此时锚校验空过，**截断到 0 = 清空对话**，与决策 3『任意深度』一致」一类方向），消除与 L125 规范流程、决策 3 的冲突；若作者本意确为「count=0 不截断」，则需同步修订决策 3 与 §3.4（空历史首轮 checkpoint 仅回文件），并与概设 §5.1「截断 History 至该 checkpoint 对应轮次前」的偏差显式登记——二选一，不可保留现状的双读法。
