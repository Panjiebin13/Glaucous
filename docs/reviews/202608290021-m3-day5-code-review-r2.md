- **维度**：逻辑正确性（健壮性增强）
- **代码位置**：`src/glaucous/ui/theme.py:81-82` `if sys.platform == "win32" and sys.stdout.isatty(): os.system("")`。
- **说明**：`os.system("")` 借 `cmd.exe` 启动时在共享控制台句柄上置位 `ENABLE_VIRTUAL_TERMINAL_PROCESSING`，是社区通用手法且与代码库既有风格一致；失败时仅返回非零码不抛异常，回退为改动前行为（无回归）。仅建议在后续迭代中考虑经 `ctypes` 直接 `SetConsoleMode`（rich 探测同源依赖）并包裹异常，摆脱对 `cmd.exe` 的隐式依赖——不阻塞本轮。

## 三、theme.py 补充改动专项评审（非 r1 所列，主代理自查发现）

**改动**：`make_console()` 在 `sys.platform == "win32" and sys.stdout.isatty()` 时先执行 `os.system("")`，使 conhost 启用 VT 处理，`detect_legacy_windows` 返回 False，rich 改走 VT 转义路径。

**问题定性核验（修复动机是否成立）**：
- rich 源码 `_write_buffer`（console.py 1446-1463）：Windows 下若 `legacy_windows=True` 且 fileno∈{0,1,2}，经 `LegacyWindowsTerm`（`_win32_console` 的 WriteConsoleW）直写，**绕过 Python 文本流**——cli.main 的 `errors="replace"` reconfigure（cli.py:459-461）对该路径无效，意象符（☁/❄/🌅 类符号在 cp936 下编码失败，其中 🌅 在 BMP 之外）确实会抛 `UnicodeEncodeError`；
- 该崩溃路径违反 FR-34「降级不崩溃」与 spec §8 风险表 cp936 行「最坏降级为可读不崩溃」承诺，定性为真实缺陷、修复正当；
- `get_windows_console_features` 以 `GetConsoleMode` 的 `ENABLE_VIRTUAL_TERMINAL_PROCESSING` 位判定 VT——`cmd.exe` 启动时在共享控制台句柄置该位是通用手法，启用后 `detect_legacy_windows` 为 False 的因果链成立（本机无 TTY 无法交互终验，依赖主代理实机自检 + 机制静态核验）。

**正确性与不引入新问题核验**：
- 守卫条件完整：非 win32 / 非 TTY 均不执行，测试与管道场景（基线回归依赖）零影响（实测 `isatty()=False` 路径无副作用，64 用例全绿）；
- 失败兜底安全：`os.system` 异常场景（cmd 不可用）仅返回非零码不抛异常，回退改动前行为，无新崩溃面；
- 老式无 VT 控制台的 conhost：`cmd` 置位失败则探测结果不变，行为同改动前，无回归；
- 与既有降级顺序兼容：该调用在 `make_console` 内、no_color/`GLAUCOUS_COLOR` 分支之前，且各分支均带 `theme`，「降级单一出口」约束未被破坏；
- 波及面核查：调用方仅 `cli.repl()`（cli.py:368）一处；`errors="replace"` 兜底（cli.py:459-461）原样保留，双保险并存；prompt_toolkit 输入层与命令渲染（commands.py）不经本改动路径，不受影响。

**结论**：改动正确、最小化、有据可查，未引入新问题；仅两条健壮性/文档同步建议（见上）。
