# Glaucous需求文档

- 版本：v3.2（2026-08-27）
- 产品定位：Glaucous 是一个运行在终端中的编程智能体。用户打开一个项目文件夹，用自然语言下达需求；智能体默认以 **Plan 模式**（只读）探索项目、产出方案，经用户授权后切换 **Build 模式**执行修改。全程在**工作区边界与分级审批**管控之下；环境难题可求助用户，规则与经验分别沉淀为 glaucous.md 与长期记忆。
- 目标用户：开发者（个人使用）；评委（考察设计完整性与工程成熟度）。
- 术语约定：

| 术语 | 含义 |
|---|---|
| Plan 模式 | 只读探索与方案产出，不可修改任何文件 |
| Build 模式 | 执行修改的工作模式，写操作按授权策略审批 |
| 授权策略 | 用户在开始构建时的授权选择：每次请求权限 / 同意所有权限 |
| 工作区 | 用户打开并授权智能体操作的文件夹 |
| glaucous.md | 记录项目规则的文件（全局与项目两级） |
| 长期记忆 | 跨会话保留的环境事实与经验 |
| Skill | 用户可注册的领域能力包 |

## 1. 总体需求

### 1.1 核心能力（P0）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-01 | 自然语言下达编程任务，智能体自主完成 | 对"修复某 bug / 添加某小功能 / 补充测试"类任务，可端到端完成并汇报 |
| FR-02 | 文件读写与编辑 | 支持读取、新建、精确编辑、目录浏览、按内容/名称搜索 |
| FR-03 | 执行终端命令 | 在工作区内执行 shell 命令，支持超时控制与后台运行，输出流式可见 |
| FR-04 | 任务过程透明 | 每一步动作（工具、参数、结果、耗时）实时可见，可事后复盘 |
| FR-05 | 会话持久化 | 会话可保存、恢复续聊；中断后不丢失现场 |

### 1.2 双模式与权限（P0，产品第一亮点）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-06 | Plan 模式（默认进入） | 只读：可浏览、搜索、运行只读命令、提问澄清；任何文件写入与状态修改命令均不可用 |
| FR-07 | 方案产出 | 用户输入需求后，智能体在 Plan 模式探索并产出结构化方案（目标/澄清/设计/步骤/风险） |
| FR-08 | 模式切换确认 | 产出方案后请求切换 Build，呈现三选一：①开始构建，每次请求权限；②开始构建，同意所有权限；③继续讨论一下（留在 Plan 修订方案） |
| FR-09 | Build·每次请求权限 | 每个写操作（文件修改、写命令）单独弹出审批卡片，附文件 diff 或命令全文 |
| FR-10 | Build·同意所有权限 | 本次构建期间写操作不再逐项询问；但工作区外访问与破坏性命令（如删除文件、强制推送）仍单独醒目确认 |
| FR-11 | 每次审批三选项 | 同意 / 同意同类型（本会话同类操作不再询问）/ 拒绝（可附理由） |
| FR-12 | 拒绝可被理解 | 拒绝并附理由后，智能体不得原样重试，应调整方案或询问用户 |
| FR-13 | 工作区边界 | 启动时以指定文件夹或当前目录为工作区；只能自由读写工作区内部，区外访问须用户逐次审批 |
| FR-14 | 边界防御 | 路径穿越、符号链接指向工作区外等绕过尝试均被拦截 |
| FR-15 | 模式回归 | 任务完成后自动回到 Plan 模式；用户可随时用命令手动切换或退出 |
| FR-16 | 审计日志 | 所有审批决策留痕（时间、操作、用户选择），可查看 |

### 1.3 人机协作（P0，产品第二亮点）

|编号 | 需求 | 验收标准 |
|---|---|---|
| FR-17 | 环境难题求助 | 遇到自身无法解决的问题（找不到 JDK / 解释器、缺凭证、任务歧义）时主动提问，问题具体可答、可附候选答案 |
| FR-18 | 求助有节制 | 环境类失败先自行重试（默认 2 次），无果再求助，不得动辄提问 |
| FR-19 | 答案可沉淀 | 用户回答中的环境事实可保存为长期记忆，后续会话不再重复询问 |

### 1.4 记忆系统（P0）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-20 | glaucous.md 规则记忆 | 支持全局（跨项目）与项目两级 glaucous.md，记录开发规则（如"Java 项目统一 Java 8"）；每次会话自动生效 |
| FR-21 | 事实记忆 | 环境事实（解释器路径、构建命令）跨会话保留，分全局/项目两个作用域，可查看、新增、删除 |
| FR-22 | 记忆分层不互污 | 规则与事实分别存储、分别注入；智能体自动提炼的记忆须用户确认后入库 |
| FR-23 | 项目规则生成 | 首次使用可扫描项目生成 glaucous.md 初始草稿，经用户确认后生效 |

### 1.5 上下文管理（P0）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-24 | 上下文压缩 | 长会话自动分级压缩：工具输出截断（完整输出可回取）→ 历史裁剪（保留调用摘要）→ 摘要压缩；截断不丢数据，压缩后任务目标与当前方案不丢失 |
| FR-25 | 占用可见 | 界面常驻上下文占用指示（百分比/进度条），达到阈值时预警并建议/自动执行压缩 |

### 1.6 扩展能力（P1）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-26 | 模型注册 | 用户可注册多个模型档案（服务地址、模型名、密钥环境变量），注册时校验连通性；密钥不出现在任何入库文件中 |
| FR-27 | 模型切换 | 会话中可随时切换模型，历史对话无缝延续 |
| FR-28 | Skill 注册 | 以"目录 + 说明文件"注册领域能力（如部署流程、代码评审清单）；智能体在相关任务中自动识别并应用 |
| FR-29 | 复杂任务的方案深度 | 复杂需求下，Plan 模式可经提问澄清后产出包含澄清记录、设计、任务清单的完整方案 |

### 1.7 视觉与易用性（P0）

| 编号 | 需求 | 验收标准 |
|---|---|--- |
| FR-30 | Glaucous 清凉主题 | 以天青（#3AA6B9）与蓝色系为主色调；界面清爽简洁、视觉密度克制：常规操作以单行+摘要呈现，仅审批/提问/方案确认等需人介入时刻使用卡片；配色兼容降级（truecolor/256/16 色）；交互文案朴素直白，图标点缀不堆砌修辞 |
| FR-31 | 状态一目了然 | 界面常驻：当前模式（Plan/Build 徽标）、模型、上下文占用 |
| FR-32 | 安装运行简单 | 一条命令安装；打开文件夹 + 一条指令即可开始；README 步骤 ≤ 5 步 |
| FR-33 | 凭据安全 | API key 仅经环境变量/未入库配置提供，仓库中零凭据 |

### 1.8 运行环境（P0）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-34 | 平台支持 | Linux（一等公民，WSL2 兼容）；不承诺 Windows 原生，但基本兼容性不崩（路径/编码/换行处理健壮） |

## 2. 典型使用场景

**场景 A：日常修 bug**
用户在 Plan 模式说"测试跑不过，帮我修一下"。智能体只读探索：跑测试、读代码、定位根因，产出修复方案。用户选"开始构建，每次请求权限"→ 每处修改弹出 diff 审批 → 修复落盘、测试转绿 → 自动回到 Plan 模式。

**场景 B：环境求助与记忆沉淀**
Build 中构建失败，找不到 JDK，自行重试 2 次无果 → 询问用户"未找到 JDK，请提供路径或让我继续搜索"。用户给出 `/usr/lib/jvm/java-8` → 完成构建，将该路径存入项目记忆；下次会话直接使用，不再询问。

**场景 C：全放行下的底线拦截**
用户选了"开始构建，同意所有权限"。构建中智能体请求 `git push --force` → 仍弹出红色醒目确认；读取工作区外配置 → 仍需单独同意。其余写操作静默执行，任务流畅完成。

**场景 D：方案迭代**
用户："给项目加用户认证模块"。智能体在 Plan 模式产出方案 → 用户选"继续讨论一下"并提出调整 → 方案修订 → 用户确认开始构建，按任务清单逐项实现并勾选进度。

**场景 E：规则约束生效**
项目 glaucous.md 写有"禁止改动 generated/ 目录"。Build 中智能体的修改方案涉及该目录 → 被规则拦截提示，智能体改道不触碰该目录。

## 3. 需求优先级与裁剪原则

| 优先级 | 范围 | 说明 |
|---|---|---|
| P0 | FR-01~25、30~34 | 核心可用 + 双模式权限 + 人机协作 + 双层记忆 + 上下文管理 + 视觉主题，缺一即不完整 |
| P1 | FR-26~29 | 模型注册切换、skill、复杂方案深度；时间不足时按 skill → 自动记忆提炼 → /init 生成顺序裁剪 |

裁剪底线：核心链路、Plan/Build 模式与权限审批、工作区沙箱、上下文管理、glaucous.md 注入为不可裁剪项。

## 4. 约束与合规（源自赛事规则，逐项硬约束）

1. 不使用任何 agent 框架/SDK（LangChain、LlamaIndex、OpenAI Agents SDK、Claude Agent SDK、AutoGen、CrewAI 等均禁止）；不允许在现成 agent 产品上封装界面。对话历史与上下文管理、工具定义与本地执行、模型输出解析、循环终止条件、错误处理均为自研。
2. 不依赖模型厂商托管的服务端工具（如 Code Interpreter、Files API）；一切执行发生在本机。
3. 允许使用模型厂商 API 客户端库、OpenAI 兼容网关及模型原生 tool calling 接口。
4. 凭据（API key 等）仅经环境变量或未入库配置文件提供，不得出现在仓库、README.txt 或视频中；若曾误提交，立即作废更换。
5. 运行语言 Python 3.11+，CLI 形态，Linux 一等公民（开发于 WSL2）；agent 运行时调用的模型不限。
6. 允许并鼓励使用 AI 工具辅助开发，但须对项目中的每一处设计负责（面试需能为设计决策辩护）。
