权限矩阵

放不放行，只看一件事——核心判据：有无兜底
工作区是 Git 仓库 ⇒ 快照可精确回退 ⇒ 区内操作放开；兜不住的地方，坚决拦住
操作 Git 工作区（有快照兜底） 非 Git 工作区（无兜底） 为什么
区内读文件含 .glaucous/ 运行日志 ✓ 放行 ✓ 放行 读，没有完整性风险
区内写文件write_file / edit_file ✓ 免审checkpoint 可回退 ◐ WRITE 审批 改坏了？一条命令回退
区内危险命令目标全部在区内 ◐ WRITE · 可豁免保留一次确认 ✕ DANGEROUS 可回退，但值得问一句
区外读文件 ◐ WRITE · 可豁免 ◐ WRITE · 可豁免 环境探测是真实需求，但要可见
区外写文件 ✕ DANGEROUS · 不可豁免 ✕ DANGEROUS 快照管不到，没有回退面
.glaucous/ 写 ✕ DANGEROUS · 恒拦 ✕ DANGEROUS · 恒拦 快照刻意排除 + 审计防篡改底线
远端 / 系统侧操作push --force · sudo · curl|sh ✕ DANGEROUS · 恒拦 ✕ DANGEROUS · 恒拦 本地快照兜不住远端与系统
放行 / 免审 —— 有兜底，让它跑
WRITE 审批 —— 问一句，可同类型豁免
DANGEROUS —— 坚决拦住，auto-approve 也越不过
恒定守卫 · 之一 .glaucous/ 写入恒拦：审计日志与会话数据不可被智能体篡改，且快照不覆盖此目录
恒定守卫 · 之二 区外写入恒拦：工作区之外没有回退面，任何授权策略都不可豁免
恒定守卫 · 之三 git push --force 恒拦：远端历史一旦被覆盖，本地快照也无能为力
Glaucous · 三级定级（SAFE / WRITE / DANGEROUS）× 授权策略（auto-approve / per-action）· 全部决策写入 audit.log 审计留痕
