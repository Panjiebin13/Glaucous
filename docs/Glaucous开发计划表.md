## 风险预案（时间不够时的裁剪顺序）

按此顺序砍，砍到 M0+M1 仍是一个合规且完整的提交：

1. skill 系统（M3.5）→ 2. /init 草稿生成（手写兜底）→ 3. 终端降级（只保 truecolor）→ 4. 模型注册多档案（环境变量单模型兜底）→ 5. 亮色主题 → 6. 评测集缩减至 8 个任务

**不可裁剪底线**：M0 原型闭环 + M1 权限成型 + 基础主题。这三样构成「能跑、可控、有辨识度」的最低完整产品。

## 每日节奏

- **每天收尾前**：当天代码 push（真实历史是评分素材），在仓库根维护一个 TODO.md 勾选进度。
- **每个里程碑收尾**：在真实项目上跑一次完整场景，确认没引入回归。
- **commit 粒度**：一个任务一个 commit，message 用中文写清做了什么——评委看得到开发过程。
