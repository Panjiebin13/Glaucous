- 版本：v1.1（2026-08-29）
- 前序：[Glaucous开发计划表.md](Glaucous开发计划表.md)（v1.0，截止 9/2 提交）——v1.0 排期保留不动，本表为赛后演进排期

## 风险预案（时间不足时的裁剪顺序）

按此顺序砍，砍到 M1+M2+M5（最小 spec 闭环）仍是完整可讲的 v1.1：

1. /fork（FR-48）→ 2. /stats（FR-49）→ 3. 评审深度介入模式（只保全自动）→ 4. 任务级 checkpoint（保对话级）→ 5. 代码评审循环（并入验收报告人工看）→ 6. v1.1 评测集缩减至 5 用例

**不可裁剪底线**：默认 Build + 底线守卫（FR-35/36）、spawn_agent 上下文隔离（FR-61/64）、checkpoint 对话级回退（FR-40/42）、Spec 单评审循环 + 按清单执行 + 验收（FR-53~56/58）。这四样构成「高自动化、可信、工程化」的 v1.1 最低完整形态。

**另设技术观察项**（不裁剪，但预研半天）：默认 Build 下「不澄清就蛮干」若评测不达标，升级「首轮写操作前一次性提示」机制（概设 §13 风险表第 1 条）。

## 每日节奏（继承 v1.0）

- **每天收尾前**：当天代码 push（一个任务一个 commit，中文 message）；TODO.md 勾选进度。
- **每个模块收尾**：既有测试全绿（硬门槛）+ 在真实项目上跑一次对应验收场景，确认无回归。
- **Git 策略**：延续完整提交历史；v1.1 提交照常推进，分支策略维持单主干。
