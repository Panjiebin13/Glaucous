# Glaucous 需求文档（v1.1）

- 版本：v1.1（2026-08-29）
- 前序版本：[编程智能体需求文档.md](编程智能体需求文档.md)（v3.2，对应产品 v1.0）——本文在其基础上演进，继承需求不重复列出，被修订项显式声明
- 产品定位：Glaucous 是一个运行在终端中的**高自动化、面向长任务**的编程智能体。启动即处于 **Build 模式**：用户以自然语言下达需求，智能体先澄清关键内容再动手——小任务直接执行（auto-approve + 底线守卫），大任务进入 **Spec 流程**（需求澄清 → 起草 → 评审循环 → 按任务清单执行 → 代码评审 → 验收归档）。多 agent 协作中，**评审由子 agent 承担、执行由主 agent 承担**；**checkpoint 回退**与**工作区沙箱**构成安全兜底，让高自动化不失控。
- 一句话定位：*「别的 agent 比谁更自主，Glaucous 比谁既能干又可信。」*
- 目标用户：开发者（日常与小任务）；进行大规模重构/特性开发的长任务用户。
- 术语约定（新增部分）：

| 术语 | 含义 |
| --- | --- |
| 底线守卫 | 即使 auto-approve 也永远单独醒目审批的操作集合：工作区外访问、破坏性命令 |
| Spec | 大任务的规格文档：需求/约束/任务清单/验收标准，一等公民产物，有独立生命周期 |
| Spec 评审循环 | 起草后由评审子 agent 按结构化检查清单评审、主 agent 修订的循环（≤3 轮） |
| 代码评审循环 | Spec 执行完成后，评审子 agent 对照验收标准与 diff 评审、主 agent 修复的循环（≤3 轮） |
| Checkpoint | 对话级检查点：基于 Git 记录当时工作区文件状态，供回退 |
| 子 Agent | 经 spawn_agent 派生的 AgentLoop 实例，独立上下文执行子任务，报告回传父 agent |
| 会话索引 | 用户级会话元数据索引文件，支撑跨项目列表与搜索 |

## 2. 新增需求

### 2.1 模式体系重构（P0，行为基座）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-35 | 默认 Build 模式 | 启动即处于 Build 模式，具备完整读写执行能力；状态栏徽标正确显示 |
| FR-36 | 默认授权策略：auto-approve + 底线守卫 | 默认策略下写操作静默执行不弹卡；**工作区外访问与破坏性命令（rm -rf、git push --force、sudo、curl \| sh 等）仍单独醒目确认**；per-action 保留为用户可选策略 |
| FR-37 | 先澄清后开发 | system prompt 约束：动手前必须明确需求边界，需求含糊时先 ask_user 澄清；评测集含"模糊需求"用例验证澄清行为 |
| FR-38 | 高风险主动确认 | agent 判断任务风险较高（大范围重构、删除文件、修改配置等）时，主动出方案确认卡请求用户批准后执行；普通任务不打断 |
| FR-39 | Plan 研究模式 | /plan 显式进入只读研究模式（写工具声明层隐藏，v1.0 机制复用）；产出分析结论与建议；/build 或口头确认回到 Build |

### 2.2 Checkpoint 回退（P0，安全兜底）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-40 | 对话级检查点 | 每轮用户任务开始前自动创建 checkpoint（基于 Git 快照，不污染用户工作树与 stash 列表）；非 Git 工作区明确提示不可用原因 |
| FR-41 | 检查点保留策略 | 保留最近 50 个 checkpoint（数量可配置），超出自动淘汰最旧；存储可查 |
| FR-42 | 一键回退 | /rollback 可回退到保留期内任意 checkpoint；默认只回退文件、保留对话上下文；提供"同时回退上下文"选项；回退前展示将变更的文件清单并确认 |
| FR-43 | 审批拒绝联动回退 | 用户拒绝审批时可选择"拒绝并回退"，自动回退到本轮任务开始前的 checkpoint |

### 2.3 会话管理增强（P0，长任务基础设施）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-44 | 用户级会话存储 | 会话文件迁移至 ~/.glaucous/sessions/<project-hash>/，按项目目录哈希分目录；meta 记录原工作区路径 |
| FR-45 | 会话索引 | 侧边 JSON 索引文件记录全部会话摘要（id/名称/工作区/时间/消息数/token）；列表秒回；索引损坏可从 JSONL 重建 |
| FR-46 | 会话命名 | 新会话自动取首条用户消息摘要为默认名；/rename 随时覆盖 |
| FR-47 | 会话列表与搜索 | /sessions 跨项目列出全部会话（名称/更新时间/消息数/工作区），支持按项目过滤；/sessions <keyword> 按名称搜索 |
| FR-48 | 会话分叉 | /fork 从当前会话状态复制全部历史创建新会话（另存为语义），新会话独立演进。**仅支持当前会话整体 fork**：不支持历史节点分叉、不支持对任意历史会话 fork（P1 增强，见 §4） |
| FR-49 | 会话统计 | /stats 展示当前会话/全局统计：消息数、token 用量、审批决策分布 |
| FR-50 | 切换语义与保护 | 切换会话只恢复对话历史、**不动文件**；检测到工作区有未提交修改时提示；Build 中途阻止切换并说明 |
| FR-51 | 旧会话自动迁移 | 启动时检测工作区旧路径 .glaucous/sessions/ 的 v1.0 会话文件，自动迁移到用户级存储并更新索引，对用户透明 |

### 2.4 Spec 一等公民（P0，差异化招牌）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-52 | 两轨道分工 | 小任务走 Plan/Build（轻量方案+直接执行）；大任务走 Spec 流程；/spec 显式发起，agent 亦可在大任务上主动建议 |
| FR-53 | Spec 进入门槛 | /spec 触发后 agent 必须先澄清需求（ask_user 访谈关键决策点），用户确认需求清楚后才进入起草；不得在需求未澄清时进入评审循环让用户漫长等待 |
| FR-54 | Spec 文档产物 | Spec 独立落盘 .glaucous/specs/<id>.md：需求与边界/澄清记录/约束/设计/任务清单/**结构化验收标准**/风险 |
| FR-55 | Spec 评审循环 | 起草后进入评审循环（≤3 轮）：评审子 agent 按结构化检查清单产出评审报告（阻塞级/建议级问题），主 agent 修订；开始时用户选全自动或深度介入模式（每轮可提建议） |
| FR-56 | Spec 批准与执行 | 评审通过后呈现 Spec 请用户批准；批准后主 agent 按任务清单逐项执行（任务进度可见），**每任务一个 checkpoint**，执行期间 Spec 以轻量锚注入、全文可回读 |
| FR-57 | 代码评审循环 | 执行完成后进入代码评审循环（≤3 轮）：评审子 agent 对照验收标准与代码 diff 评审，主 agent 按发现修复后复审；通过或轮次耗尽出验收报告 |
| FR-58 | 验收与归档 | 验收报告对照结构化验收标准逐项核验并给出结论；Spec 状态机闭环（verified/archived），全程可查 |
| FR-59 | Spec 管理命令 | /spec 发起流程；/specs 列出全部 Spec 及状态；/spec status 查看当前 Spec 执行进度与验收核验结果 |

### 2.5 多 Agent 协作（P0·先行开发，供评审复用）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-60 | spawn_agent 工具 | 父 agent 经工具派发子任务（任务描述+可选上下文）；调用时机可在 skill/Spec 中显式约定（如评审环节固定用子 agent） |
| FR-61 | 子 agent 上下文隔离 | 子 agent 拥有独立 History、独立 system prompt、独立 token 预算；**不占用父 agent 上下文**——父 agent 只收到最终报告 |
| FR-62 | 权限继承与独立审批 | 子 agent 继承父 agent 当前授权策略；工作区沙箱与危险命令分类同等生效；需要审批时**子 agent 独立弹审批卡**（标注子 agent 身份与所属父任务），审计日志记录归属 |
| FR-63 | 结构化报告回传 | 子 agent 完成后生成结构规范的任务报告（结果摘要/修改文件清单/验证结果/风险与遗留）回传父 agent，作为工具结果入父史 |
| FR-64 | 串行执行与禁止嵌套 | 第一版子 agent 串行执行（父等待子完成再继续）；子 agent 工具集 = 父 agent 工具集去掉 spawn_agent，不允许嵌套派生 |

## 3. 典型使用场景

**场景 F：小任务直接干（默认 Build）**
用户："把 utils.py 里的日期格式化函数改成支持时区参数。"智能体先确认函数位置与期望行为（一句澄清），简述做法后直接修改并跑测试。全程仅危险操作才弹审批，任务一次完成。（对应 v1.0 场景 A 的轻量化演进）

**场景 G：大任务 Spec 全流程**
用户："给项目加用户认证模块。"智能体判断规模较大，建议 /spec。用户确认后：澄清访谈（会话存续方式？密码哈希方案？）→ 用户确认需求清楚 → 起草 Spec（含任务清单与验收标准）→ 评审子 agent 两轮评审（第 1 轮发现"未定义密码强度策略"，修订后通过）→ 用户批准 → 主 agent 按任务清单逐项执行，每任务 checkpoint → 代码评审子 agent 对照验收标准复审一轮通过 → 验收报告归档。

**场景 H：改坏了，一键回退**
Build 中智能体重构了模块，测试大面积转红。用户 /rollback → 展示将还原的文件清单 → 确认后工作区回到本轮任务开始前状态；对话上下文保留，用户指着对话说"按刚才方案 B 来"继续。

**场景 I：跨会话续接长任务**
昨天的认证模块 Spec 执行到第 4/7 个任务。今天 cd 到项目目录，/sessions 看到"用户认证模块"会话 → 恢复后 Spec 锚与任务进度就位，从第 5 个任务继续，/spec status 随时查看进度。

**场景 J：全放行下的底线拦截（继承场景 C，默认策略下依然成立）**
默认 auto-approve 策略下，构建中智能体请求 `git push --force` → 红色醒目确认卡；读取工作区外配置 → 单独同意。其余写操作静默执行。

（v1.0 场景 A~E 继续有效，其中场景 A/D 的模式前置描述按新默认模式修订。）

## 4. 需求优先级与裁剪原则

| 优先级 | 范围 | 说明 |
| --- | --- | --- |
| P0 | FR-35~43、FR-44~51、FR-52~59、FR-60~64 | 模式重构、checkpoint、会话管理、Spec、多 Agent——v1.1 完整形态，缺一即不完整 |
| P1 | 会话内容全文搜索、/fork 历史节点分叉、并行子 agent、澄清机制加固（B 方案） | 登记为后续增强。其中「/fork 历史节点分叉」经 2026-08-30 需求确认**显式裁剪**：v1.1 的 fork 仅支持当前会话整体复制（FR-48 语义收窄确认），历史节点分叉不在 v1.1 范围内 |

裁剪底线（不可裁剪项）：默认 Build + 底线守卫、checkpoint 回退、Spec 双评审循环、spawn_agent 上下文隔离。若时间不足，会话管理的分叉/统计可先裁（FR-48/49），其余不裁。

## 5. 约束与合规（继承 v1.0，逐项仍有效）

1. 不使用任何 agent 框架/SDK；子 agent = 自研 AgentLoop 实例化复用，非框架能力；对话历史、上下文管理、工具执行、输出解析、循环终止、错误处理均自研。
2. 不依赖模型厂商托管服务端工具；一切执行在本机。
3. 允许 OpenAI 兼容客户端与原生 tool calling。
4. 凭据仅经环境变量/未入库配置提供，仓库零凭据。
5. Python 3.11+，CLI 形态，Linux 一等公民（WSL2 开发）。
6. 新增：checkpoint 依赖 Git（工作区自带或系统安装的 git 命令），不引入 Git 库依赖，经子进程调用；非 Git 工作区行为见 FR-40。
