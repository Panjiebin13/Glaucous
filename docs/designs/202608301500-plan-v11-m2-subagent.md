## 一、总体架构

```
父 AgentLoop（主 agent，History 不变）
  └─ dispatch(spawn_agent 调用)                       ← 父视角唯一可见的一次调用
       └─ SubagentRunner.run(task, context)           ← agent/subagent.py（同步 await，天然串行）
            ├─ build_sub_registry(父 registry)         ← 去掉 spawn_agent 的工具全集（防嵌套）
            ├─ History.create(SUB_PROMPT, workspace, subdir="agents")   ← 独立 History + 独立会话文件
            ├─ SessionState 独立副本（快照复制父当前值）→ ApprovalPipeline(agent_label=child-N)
            ├─ ReplContext.active_state / active_agent 切换（submit_plan/ask_user 副作用隔离与卡标）
            ├─ AgentLoop(llm, sub_registry, sub_history, 子 state, ...)   ← 复用父 loop 参数
            │    └─ 中间过程经 on_event 包装为 sub_event 事件（UI 可见，不回传父史）
            └─ 结构化报告 → ToolResult（父史仅增 assistant+tool 两条）
```

分层影响分析：

| 层 | 模块 | 影响 |
|---|---|---|
| 工具层 | `tools/spawn_agent.py`（新增） | SpawnAgentTool，SAFE 风险级，全模式可用，委托 runner |
| Agent 层 | `agent/subagent.py`（新增） | SubagentRunner：子 registry/History/pipeline/loop 构造与运行、报告拼装 |
| 权限层 | `permission/approval.py` | ApprovalPipeline 增 agent_label/agent_task；ApprovalAction 增 origin/origin_task；审计事件增归属字段 |
| 状态层 | `commands.py` | ReplContext 增 `active_state` / `active_agent` 字段（confirm/ask 卡读，runner 切换） |
| 事件层 | `agent/loop.py` | **零改动**（AgentLoop 直接复用，子 loop 实例化即用） |
| UI 层 | `cli.py` / `ui/prompts.py` | render_event 增 sub_* 三分支；审批/方案/提问卡标注子 agent 归属；build_sub_agent_prompt 新增 |
| 接线层 | `cli.py` build_registry / rebuild_loop | 仅主 registry 注册 spawn_agent；runner 组装 |
| 持久层 | `context/history.py` | create_session_file/create 增 subdir 参数（默认 "sessions"，向后兼容） |

## 二、任务 2.1：spawn_agent 工具（FR-60）

### 2.1 工具契约（`tools/spawn_agent.py`）

```python
class SpawnAgentTool(Tool):
    name = "spawn_agent"
    description = (
        "派发子任务给子 agent 串行执行（如：独立评审、隔离上下文的大块探索）。"
        "子 agent 拥有独立上下文与权限管线，完成后仅回传结构化报告；"
        "禁止嵌套派发。"
    )
    parameters = {
        "type": "object",
        "required": ["task"],
        "properties": {
            "task": {"type": "string", "description": "子任务描述（完整、自包含）"},
            "context": {"type": "string", "description": "补充上下文（可选：相关文件/约束/验收标准）"},
        },
    }
    modes = ALL_MODES   # Plan 下可派发只读评审任务；子 agent 模式取派发时父模式快照（独立副本，§4.3）
    risk = Risk.SAFE    # 派发本身无副作用；子任务内部操作照常走权限管线

    def __init__(self, runner: "SubagentRunner") -> None: ...
    async def execute(self, task: str, context: str = "") -> ToolResult: ...
```

- execute 契约：`result = await runner.run(task, context)`；成功时 `ok=True`、`content=结构化报告`；runner 内未捕获异常由 dispatch 统一收口（回喂「工具 spawn_agent 执行异常」）。
- **仅主 agent 注册**：注册点只有 `cli.build_registry`（主 registry）；子 registry 经 `build_sub_registry` 构造时排除本工具（§三）。

## 三、任务 2.2：子 AgentLoop 构造（FR-61/64）

### 3.1 `agent/subagent.py` — SubagentRunner

```python
@dataclass
class SubAgentInfo:
    agent_id: str          # "child-<N>"（自增序号，与审计 agent 字段同源）
    task: str
    session_file: Path

class SubagentRunner:
    def __init__(
        self,
        llm: LLMClient,
        parent_registry: ToolRegistry,
        state: SessionState,             # 父 state：构造时快照复制，绝不共享实例
        audit: AuditLog,
        decision_callback: DecisionCallback,  # 与父 pipeline 同源
        workspace: Path,
        rules: str,                      # glaucous.md 规则全文（接线时 load_rules 传入，r1-B2）
        max_steps: int,
        context_limit: int,
        outputs_dir: Path | None,
        plans_dir: Path | None,
        on_event: LoopEvent | None,      # 主 on_event（包装为 sub_* 事件发出）
        ctx: "ReplContext",              # 归属切换载体（active_state/active_agent/active_task）
    ): ...

    async def run(self, task: str, context: str = "") -> ToolResult: ...
```

`run()` 流程（严格串行，await 到返回才回到父 loop）：

1. **task 入口校验**（r1-S3）：`task.strip()` 为空 → 直接返回 `ok=False` 回喂「子任务描述不能为空」（schema required 仅拦缺失不拦空串，runner 兜底）。
2. **agent_id 分配**：`child-<序号>`（runner 内自增计数，进程生命周期内唯一；审计字段值与概设 §8.3 对齐：主 agent 为 `main`）。
3. **子 state 副本**：`child_state = SessionState(mode=父.mode, approval_policy=父.approval_policy, approved_types=set(父.approved_types))`——快照复制，此后与父完全隔离。
4. **独立 History**：`History.create(build_sub_agent_prompt(task, context, workspace, rules), workspace, subdir="agents")` → 会话文件 `.glaucous/agents/<stamp>-<hex>.jsonl`（任务 2.2 计划表要求）。
5. **子 pipeline**：`ApprovalPipeline(child_state, callback=decision_callback, audit=audit, agent_label=agent_id, agent_task=task)`。
6. **子 registry**：`build_sub_registry(parent_registry)`——新建 `ToolRegistry` 实例，注册父 registry 的**全部工具实例**（共享工具对象，工具自身无 per-agent 状态；解析熔断计数在 registry 层，天然隔离），**排除 name == "spawn_agent"**（FR-64 防嵌套：声明层不可见 + 执行层「工具不存在」双保险）；`set_approval_pipeline(子 pipeline)`。submit_plan / ask_user 保留在子工具集（概设 §8.3），副作用隔离见步骤 7。
7. **归属切换（try/finally 保证恢复）**：
   - `ctx.active_state = child_state`（confirm 闭包内 `enter_build` 作用于子副本，父模式不受影响）；
   - `ctx.active_agent = agent_id`、`ctx.active_task = task`（审批/方案/提问卡头标注「🕊 子 agent（任务：…）」）；
   - finally 恢复为哨兵：`ctx.active_state = None` / `active_agent = "主 agent"` / `active_task = ""`（r2-B4 修复：active_state 恢复 None 哨兵而非 ctx.state 实例——实例值会在 /clear、/resume 整体替换 state 后变成旧对象，违反 D8「闭包不捕获旧对象」；None 语义下 confirm 闭包动态回退 ctx.state，永远读到最新实例）。
   runner 需持有 ctx 引用（构造参 `ctx: ReplContext`，接线时传入；active_* 三字段为新增）。
8. **子 loop**：`AgentLoop(llm, sub_registry, sub_history, child_state, max_steps=父值, on_event=包装函数, context_limit=父值, outputs_dir, plans_dir)`——`agent/loop.py` **零改动**。
9. **执行**：`answer = await sub_loop.run(task + （context 的任务注入）)`；用户输入 = task 正文 + 可选 context 段（格式：`task\n\n[补充上下文]\ncontext`）。
10. **修改文件清单收集**：包装函数拦截子 loop 的 `tool_end` 事件，`call.name in {"write_file", "edit_file"}` 时从 `call.arguments` 解析 `path` 记入清单（保序去重）。
11. **报告生成**（§3.3）→ `ToolResult(ok=True, content=report, metadata={"sub_agent": agent_id, "session_file": str, "modified_files": [...]})`。

### 3.2 子 agent system prompt（`ui/prompts.py`）

- 新增 `build_sub_agent_prompt(task: str, context: str, workspace: Path, rules: str = "") -> str`（r1-B2 修复：注入段对齐概设 §8.2「子任务角色 + 工作区信息 + glaucous.md 规则 + 任务描述」）：
  1. 角色段：你是子 agent（任务执行者），由主 agent 派发，工作区为 `{workspace}`；执行完成即终止，用户不在线，**不要调用 ask_user**（评审/探索类子任务的输入已含全部材料，概设 §8.3；确需用户输入时在报告「风险与遗留」段说明）；**不使用 submit_plan**（子任务的风险判断由主 agent 在派发前完成；工具保留仅作兜底，批准只影响子会话副本，§4.4）。
  2. 工作区段：`当前工作区：{workspace.resolve()}`（与主 prompt 同格式）。
  3. 规则段：`rules` 非空时注入 `项目与全局规则（glaucous.md，必须遵守）：\n{rules}`——**全量不裁剪**（FR-20 同源语义），保证子 agent 写操作受项目规则约束。
  4. 报告规范段（硬约束）：最终回答**必须且只能**是以下四段结构（每段一行标题 + 内容）：
    ```
    【任务结果摘要】…
    【修改文件清单】…（无则写「无」）
    【验证结果】…（未验证则写「未执行验证」）
    【风险与遗留】…（无则写「无」）
    ```
  5. context 非空时追加「补充上下文」段。
  - **不注入**事实记忆与技能索引（概设 §8.2：评审员需要的是任务上下文，不是主 agent 的全部包粘）。
- BASE_PROMPT 增补一句（「多 Agent 协作」段）：何时派发子 agent（大块独立探索/评审类工作），子 agent 结果只以报告形态回到对话。

### 3.3 结构化报告（FR-63；上限 1000 字，交付后修订 2026-08-30）

- 子终答 `answer` 若已含四段标题（【任务结果摘要】等全部出现）→ 原样采用；否则由 runner 拼装：摘要 = `answer` 截断；修改文件清单 = 收集清单；验证结果 = 「未执行验证」；风险与遗留 = 「无」；
- 报告入史上限 **1000 字**（v1.1 用户决策 2026-08-30，由概设的 400 字放宽）：超限截断时**完整报告落盘** `.glaucous/outputs/spawn_agent-<agent_id>.log`，尾注附真实回取提示 `可调用 read_output(call_id="spawn_agent-<agent_id>") 分段查看`——外置型对齐 L0/read_output 既有机制（修复 e2e 实测的「父模型猜 call_id 落空」缺陷）；落盘失败降级为仅截断（尽力而为）；
- 父上下文零污染不变量不变：入史的永远只有 ≤1000 字的报告正文。

## 四、任务 2.3：权限继承与独立审批（FR-62）

### 4.1 `permission/approval.py` 改动

- `ApprovalAction` 增字段：`origin: str = "main"`、`origin_task: str = ""`（归属标注，回调侧与测试消费；取值口径与概设 §8.3 对齐）。
- `ApprovalPipeline.__init__` 增参：`agent_label: str = "main"`、`agent_task: str = ""`（默认值 = 主 agent 行为完全不变）。
- `gate()`：调用 `self._callback(action)` **之前** stamp `action.origin = self._agent_label`、`action.origin_task = self._agent_task`（auto-approve 等不放行到 callback 的路径不 stamp，无副作用）。
- `_event()`：审计事件增 `"agent": self._agent_label`；`agent_task` 非空时增 `"agent_task"` 字段（主 agent 事件保持既有字段集不变，回归零影响）。

### 4.2 CLI 交互卡标注（`cli.py`，r1-S5 对齐概设 §8.3/§9）

- 审批卡 `make_decision_callback(ctx)` 的 `decide()`：卡片首行在 `ctx.active_agent != "主 agent"` 时增一行 `[glaucous.sub]🕊 子 agent（任务：{ctx.active_task 截断 40 字}）[/]`；其余交互流程（箭头选择/伪事件/live_hooks）不变。
- 方案确认卡 `confirm` 闭包与提问卡 `make_ask_callback(ctx)` 的 `ask()`：同样读取 `ctx.active_agent`，非「主 agent」时卡头增同款归属行（概设 §8.3：子 agent 的 ask_user 直接透传给用户，但卡面可见归属）。

### 4.3 继承语义声明（快照复制，r1-B1 修复）

- 子 agent 持独立 `SessionState` 副本，构造时快照复制父当前值：
  - 父 auto-approve → 子普通写静默放行；父 per-action → 子逐条弹卡；DANGEROUS 与区外操作守卫在子 agent 内**同等生效**（gate 逻辑零改动）；
  - 子任务内的「同意同类型」只写入子副本 `approved_types`，**不回流父**（父后续同类型操作不被子任务豁免，r1-B1 ①反例消除）；
  - 子内 submit_plan 批准只翻转子副本 mode（经 `active_state`，§4.4），父会话模式不受影响（r1-B1 ②反例消除）；
  - 子任务进行中父侧状态变化不影响子（串行执行下父无状态变更操作，声明性边界）。

### 4.4 归属隔离与切换（`commands.py` + `cli.py`）

- `ReplContext` 增字段：`active_state: SessionState | None = None`（None 语义 = 等于 `ctx.state`，属性访问处统一回退）、`active_agent: str = "主 agent"`、`active_task: str = ""`。
- `confirm` 闭包（cli.py）：`ctx.state.mode == MODE_PLAN` 的判断改读 `ctx.active_state or ctx.state`；`enter_build()` 作用于该 active state——主 agent 路径行为不变（active_state 为 None 回退原字段），子任务路径作用于子副本。
- runner.run() 期间切换、finally 恢复（§3.1 步骤 7）；串行执行保证切换无竞态。

## 五、任务 2.4：事件通道与回传（FR-63）

### 5.1 事件契约（经主 `on_event` 发出，父史不可见）

| 事件 | payload | 时机 |
|---|---|---|
| `sub_start` | `{agent_id, task}` | runner.run 入口 |
| `sub_event` | `{agent_id, event, payload}` | 子 loop 每个非 sub_* 事件透传包装 |
| `sub_end` | `{agent_id, brief, ok}` | runner.run 出口（brief = 报告首段摘要 ≤80 字） |

- **会话缓冲落账（r1-S4 落点）**：`make_on_event`（cli.py）增分支——`sub_start` / `sub_event` / `sub_end` 事件追加进 `ctx.session_events`（/expand 全会话口径可回看）；text 不落账的既有规则不变。
- 父上下文零污染不变量：spawn 全程父 History 仅追加 2 条（assistant(tool_calls) + tool(result)）——由 AgentLoop 既有 dispatch 流程保证，测试固化（§8.1）。（r2-S8：引用指正）

### 5.2 渲染（`cli.py` render_event / _thinking_line）

- `sub_start`：一行 `🕊 子 agent 出发 · {agent_id} {task 截断 60}`（海盐青，概设 §9 意象）。
- `sub_event`：子事件委托既有渲染形态并加两格缩进前缀（tool_start/tool_end/text 等复用现分支的紧凑形态；text 增量在子 agent 内不做流式直出，仅折叠摘要，防与父正文缓冲交叉——实现取 `_thinking_line` 的单行形态直打或进动态区）。
- `sub_end`：一行 `⎿ 子 agent {agent_id} 完成 · {brief}`（海草绿/陶土红按 ok）。
- `_thinking_line` 增三分支（单行摘要，格式同上精简），保证折叠模式下子事件计入思考区。

## 七、错误处理策略

| 场景 | 行为 |
|---|---|
| task 为空串/纯空白 | runner 入口显式检查（r1-S3）：返回 `ok=False` 回喂「子任务描述不能为空」——schema required 仅拦缺失不拦空串（base.py 既有行为），runner 兜底 |
| 子 loop 抛异常（非 ParseCircuitBroken） | AgentLoop 自身善后（悬空 call 补推）后向上抛；runner 不捕获，交 dispatch 统一收口回喂「工具 spawn_agent 执行异常：…」，父会话不中断 |
| 子 loop ParseCircuitBroken | **子 loop 内部捕获转终止诊断**（loop.py 既有路径，r1-S3 修正：不上抛）；`answer` = 诊断文本照常拼装报告，`ok=True`，父会话不中断 |
| 子 agent 步数上限/预算耗尽终止 | 子 loop 返回终止诊断文本作为 `answer`，照常拼装报告（摘要段即诊断），`ok=True`——报告如实反映「任务未完成」 |
| 子 agent 调用 spawn_agent | 声明层不可见；幻觉调用时执行层回喂「工具 spawn_agent 不存在。可用工具：…」（registry 既有路径，零新代码） |
| 子 agent 内审批回调为 None（测试/内嵌场景） | gate 既有的「无回调拒绝」路径生效，安全侧默认 |
| `.glaucous/agents/` 写入失败 | History 落盘为尽力而为（既有 _append 语义），不阻断子任务执行 |
| runner.run() 中途异常 | 归属切换经 try/finally 恢复（§3.1 步骤 7），active_state/active_agent/active_task 不残留子任务值 |

## 八、测试与验证（计划表任务 2.5）

### 8.1 新增 `tests/test_subagent.py`（mock LLM 脚本驱动，模式同 test_mode_default_build.py）

- **隔离性（FR-61）**：脚本驱动子 agent 多步工具调用后，断言父 History 长度增量恰为 2（assistant+tool），父消息中不含子过程内容；spawn 前后父上下文 token 估算增量 = 报告文本（而非子全过程）。

- **快照继承（FR-62，r1-B1 对应用例）**：
  - per-action 策略下子 agent 写操作触发决策回调，且回调收到的 `ApprovalAction.origin == agent_id`、`origin_task == task`；auto-approve 下普通写静默放行；DANGEROUS 命令在子 agent 内走单独确认（守卫不变）；审计事件含 `agent`（`main`/`child-1` 取值）/`agent_task` 字段；
  - 子 agent 内「同意同类型」后，父 `SessionState.approved_types` 不变（不回流）；
  - Plan 模式下子 agent submit_plan 批准后：子 state 副本 mode=build、**父 state.mode 仍为 plan**（active_state 隔离），且 runner 返回后 `ctx.active_state`/`active_agent`/`active_task` 已恢复。
- **报告回传（FR-63）**：四段标题齐全；总长 ≤1000；超限截断时完整报告落盘 `outputs/spawn_agent-<agent_id>.log` 且尾注含 read_output 回取提示（ReadOutputTool 可取回）；子终答已含四段时原样采用；metadata 含 `sub_agent`/`modified_files`。
- **子会话文件**：spawn 后 `.glaucous/agents/` 下新增一个 `.jsonl` 且首行含 session_meta。
- **事件通道（r1-S4 对应用例）**：事件序列含 sub_start/sub_event/sub_end 且 payload 字段正确；`make_on_event` 收到 sub_* 事件后 `ctx.session_events` 增长（落账）；主 on_event 收到的子事件不影响父史。
- **串行性**：runner.run 期间父 loop 不推进（结构上由 await 保证，以脚本顺序断言佐证）。
- **空 task**：`task="  "` 时返回 ok=False 且不产生子会话文件。
