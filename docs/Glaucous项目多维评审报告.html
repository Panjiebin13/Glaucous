BLOCKER命令替换（$( ) / 反引号）可绕过危险命令分类器 ✅ 已修复 · 2026-09-02

分类器对复合命令（; / && / 管道）的拆分与引号感知做得细致，但未处理 shell 命令替换语法。实测探测结果：

❯ 实测（WSL 环境，CommandClassifier.classify）
'echo $(rm -rf /tmp/x)'        -> SAFE  'echo 只读/探测命令'
'echo `rm -rf /tmp/x`'         -> SAFE  'echo 只读/探测命令'
'ls $(sudo rm -rf /)'          -> SAFE  'ls 只读/探测命令'
'cat file | xargs rm -rf /'    -> WRITE（保守升级拦截）✓
  • bash 工具经 asyncio.create_subprocess_shell 真实执行，命令替换会在子 shell 中展开——SAFE 定级意味着免审批直接执行。
  • 缓释因素：工作区 cwd 限定、git 兜底区可回退、审计日志留痕；但「rm -rf ~/」类区外目标在 git 兜底区外，守卫承诺（区外恒拦）存在破口。
  • 建议：检测命令串中引号外的 $（ / ` 结构即保守升级 WRITE；或改用 shlex 预展开检测。同类问题亦见于 find -execdir bash -c "rm -rf $"（-exec 标记仅匹配字面 -exec rm）。
