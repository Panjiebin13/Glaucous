高自主 × 长任务：2+3 基座体系

长任务三座解决「跑得久」，高自主两座解决「敢自动」——装得下 · 省着用 · 不跑偏 · 敢放 · 能收
维度一 · 长任务跑得动装得下 → 省着用 → 不跑偏

1上下文工程：三级压缩 + 锚机制

容量不爆、目标不丢——长任务的物理保障
  • L1 本地裁剪（>70%）：旧轮次工具结果由执行记账派生成一行摘要，零模型开销、无幻觉；锚行豁免保留
  • L2 模型摘要（>85%）：早期历史压成 500 字摘要，并从磁盘重建锚段拼入——压缩永不丢目标
  • 预算优雅终止：压缩后仍超限则体面收尾，--resume 无损续接（输出侧另有 L0：超长输出截断落盘，可回取）
  • 锚机制：方案/Spec 全文落盘不常驻，历史里只留「路径+目标+回读入口」，按需 read_plan / read_spec 取回
实测：四目标大任务上下文峰值占用仅 8%（128K 窗口）

2子 Agent 上下文隔离

重活在独立上下文里干——容量省着用，评审自动化
  • 独立 History / system prompt / 工具集（去除 spawn_agent 防嵌套），中间过程不进主上下文
  • 回传四段式结构化报告，≤1000 字，超限落盘可回取——父上下文只增一页报告
  • 分工：评审用子 agent（隔离），执行用主 agent（可控）——Spec 评审、代码评审、验收核验全自动
效果：评审几十轮往返，主上下文增量仅报告字数级

3Spec 任务分解

方向不偏、中断能续——长任务的组织保障
  • 大任务澄清后成书面契约：任务清单 + 验收标准，逐任务受管分发（三段式消息：约束摘录 + 子任务 + 不越界）
  • 防偏移四道闸：任务内联约束 → Spec 锚随时回读 → 代码评审对照 diff 查越界 → 验收逐条核验
  • 状态即文档：勾选写回 + frontmatter 落盘，中断后 /spec 断点续跑、--resume 续会话
评测实证：v1.0 组多余输入触发范围外重构；v1.1 全程零越界
维度二 · 高自主敢放 → 能收

4权限矩阵 + 默认 Build

敢放，且默认就放——自主的开关与刹车
  • 核心判据「有无兜底」：Git 工作区内写入免审（快照可回退）；兜不住的坚决拦
  • 三道恒定守卫：.glaucous/ 写、区外写、push --force——任何策略不可豁免
  • 启动即 Build + auto-approve：任务一行下达，执行期零审批弹窗；全部决策写审计日志
实测：三用例全程 0 人工干预完成（含多文件大任务）

5Checkpoint 随时回退

能收——改坏了一条命令还原，自主的安全底座
  • 每轮任务入口自动打 Git 快照（临时索引五步法，连新增文件也捕获），保留最近 50 个
  • /rollback：变更清单确认卡（修改/删除/新增三态）→ 文件精确还原；审批「拒绝」可联动回退
  • 快照是权限放宽的前提：正因为回得去，才敢放开手
对照实证：改坏恢复——v1.1 一条 /rollback；v1.0 无回退手段，只能手工 git
