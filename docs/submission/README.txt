【如何运行】
环境：Python 3.11+。
1. 仓库目录执行：pip install -e .
2. 设置环境变量 GLAUCOUS_API_KEY（DeepSeek 或任意 OpenAI 兼容网关的密钥；凭据只经环境变量，不入库）；可选 GLAUCOUS_BASE_URL、GLAUCOUS_MODEL。
3. 执行：glaucous --workspace <你的项目目录>（或 bash start.sh）。
进入终端后以自然语言下达任务，agent 即自主读写文件、执行命令完成任务；/help 查看全部命令，/model 运行时切换模型。

【特色功能】
设计宗旨：高自主地跑长任务、尽可能少打扰用户，由「2+3」五座基座支撑。
长任务三座：
1. 上下文工程：三级压缩（本地裁剪、模型摘要、预算优雅终止）+ 锚机制——方案全文落盘不常驻、压缩后目标不丢，大任务上下文峰值占用极低；
2. 子 agent 隔离：评审等重活在独立上下文执行，只回传千字内结构化报告，主上下文不被污染；
3. Spec 任务分解：/spec 先澄清需求再生成书面规格（任务清单+验收标准），经子 agent 评审后逐任务执行，再经代码评审与逐条验收；状态落盘、中断可续跑。
高自主两座：
4. 权限矩阵：核心判据「有无兜底」——Git 工作区内写入免审；区外写、.glaucous 写、强制推送恒拦；启动即 Build 自动放行，执行期零审批弹窗；
5. Checkpoint 回退：每任务入口自动打 Git 快照（含未跟踪新增文件），/rollback 一键精确还原，审批拒绝可联动回退。

【其它说明】
核心引擎全部自研、零框架依赖：主循环与终止条件、流式工具调用拼装与解析熔断、历史持久化、工具执行、错误处理均自己实现。代码 15000+ 行，其中测试约占 45%，336 个测试全绿。
开发过程 spec 驱动：每里程碑先出约束文档、经多轮评审再编码；需求文档、概要设计、各 spec 与 40 余份评审报告全部入库（docs/），每处设计决策可追溯。
