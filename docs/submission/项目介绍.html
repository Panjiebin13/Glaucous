01它是什么

Glaucous 是一个运行在终端里的编程智能体：用户用自然语言下达任务，它自主阅读代码、编写与修改文件、执行命令、运行测试， 直到任务完成。与主流方案最大的不同在于两点—— ① 大任务走内置的 Spec 全流程（澄清 → 书面规格 → 评审 → 逐任务执行 → 验收），而不是让模型一口气蛮干； ② 安全兜底作为一等设计：每步任务自动快照，权限按「有无兜底」放行，改坏了一条命令回退。

02分层体系结构

四层结构，依赖严格单向无环。交互层负责人机界面，编排层负责「想清楚怎么干」，能力层提供工具与约束，基座层提供模型通道与持久化。

03核心：2+3 基座体系

「高自主」与「长任务」两大能力，由五座基座支撑——长任务三座解决「跑得久」，高自主两座解决「敢自动」。

维度一 · 长任务跑得动装得下 → 省着用 → 不跑偏

① 上下文工程 三级压缩 + 锚机制

  • L1 本地裁剪（占用 >70%）：旧轮次工具结果由执行记账派生成一行摘要，零模型开销、无幻觉；
  • L2 模型摘要（>85%）：早期历史压成 500 字摘要，并从磁盘重建锚段拼入——压缩永不丢目标；
  • 预算优雅终止：压缩后仍超限则体面收尾，--resume 无损续接；
  • 锚机制：方案/Spec 全文落盘不常驻，历史里只留「路径+目标+回读入口」，按需取回。
实测：四目标大任务上下文峰值占用仅 8%（128K 窗口）

② 子 Agent 上下文隔离

  • 评审等重活在独立上下文执行（独立历史/提示词/工具集，防嵌套）；
  • 只回传四段式结构化报告（≤1000 字，超限落盘可回取）；
  • 分工：评审用子 agent（隔离），执行用主 agent（可控）。
评审几十轮往返，主上下文增量仅报告字数级

③ Spec 任务分解

  • 大任务先访谈澄清，再生成书面规格（任务清单 + 验收标准）；
  • 子 agent 评审（≤3 轮）通过后，逐任务受管分发执行，再经代码评审与逐条验收；
  • 防偏移四道闸：任务内联约束 → Spec 锚回读 → 评审查越界 → 验收核验；状态即文档，中断可续跑。
对照实证：v1.0 组多余输入触发范围外重构；v1.1 全程零越界
维度二 · 高自主敢放 → 能收

④ 权限矩阵 + 默认 Build

  • 核心判据「有无兜底」：Git 工作区内写入免审（快照可回退）；兜不住的坚决拦；
  • 三道恒定守卫：.glaucous/ 写、区外写、push --force——任何策略不可豁免；
  • bash 命令经分类器动态定级（拆段取最坏）；启动即 Build 自动放行，执行期零审批弹窗。
实测：三用例全程 0 人工干预完成（含多文件大任务）

⑤ Checkpoint 随时回退

  • 每任务入口自动打 Git 快照（临时索引五步法，连新增文件也捕获），保留最近 50 个；
  • /rollback：变更清单确认卡（修改/删除/新增三态）→ 文件精确还原；审批「拒绝」可联动回退；
  • 快照是权限放宽的前提：正因为回得去，才敢放开手。
对照实证：改坏恢复——v1.1 一条 /rollback；v1.0 无回退手段，只能手工 git

07如何运行

环境 Python 3.11+，三步启动：

步骤命令说明
1pip install -e .仓库目录执行，安装主包（依赖仅 openai / rich / prompt_toolkit）
2export GLAUCOUS_API_KEY=...DeepSeek 或任意 OpenAI 兼容网关密钥；凭据只经环境变量，不入库
3glaucous --workspace <你的项目目录>进入终端后自然语言下达任务；/help 查看全部命令
