01设计哲学与三条主线

一切机制围绕一个问题：如何让智能体长时间自主工作，同时不出事、不失控、不刷屏打扰用户。三条设计主线支撑这个目标。

🧭 主线一 · 长任务跑得动

  • 大任务走 Spec 流水线：澄清 → 书面规格 → 双评审 → 逐任务执行 → 验收；
  • 子 agent 隔离评审，四级上下文压缩，长任务跑几十步上下文占用仍是个位数。

💬 主线二 · 需求先说清

  • 大任务强制澄清访谈（箭头选择卡），确认清楚才动手；
  • /fork 分叉会话先讨论想法，不污染主线会话。

🛡 主线三 · 安全是自主的前提

  • 每轮任务自动打 Git 快照（checkpoint），改坏一条命令回退；
  • 权限矩阵判据是「有无兜底」：快照兜得住就放行，兜不住坚决拦。

03多层记忆与全局约束

让智能体「记得住环境、守得住规矩」的两套机制：记忆自下而上沉淀事实，约束自上而下划定行为边界。

🧠 多层记忆体系 跨会话沉淀

  • 双作用域：全局 ~/.glaucous/memory.json（跨项目环境事实，如「本机要用 python3」）+ 项目 .glaucous/memory.json（项目专属事实）；
  • 存全量、注入裁剪：存储永不自动裁剪，注入时按最近使用取 Top-N，控制 system prompt 成本；
  • agent 可用 memory_save 主动沉淀，/memory 命令人工增删查；原子写入 + 损坏容错（宁丢不崩）。
extensions/memory.py · tools/memory_tool.py · commands.py

📏 全局约束（三层防线） 软引导 + 硬保证

  • 提示词引导层：BASE_PROMPT 工作准则——先看真实文件再回答、需求未澄清不动手修改、高风险任务主动出方案确认；
  • 规则注入层：glaucous.md 双层规则（全局 + 项目）每次启动注入，全量永不裁剪；
  • 执行硬保证层：行为约束不靠提示词——声明层过滤可用工具（如 Plan 模式无写工具），执行层在派发时校验权限与边界。
ui/prompts.py · extensions/rules.py · tools/base.py

🧰 技能系统 惰性加载

  • SKILL.md 技能文件按需 load_skill 加载，system prompt 只注入 name+description 索引，不占常驻上下文；
  • 内置技能（项目介绍、代码评审、发布清单、创建技能）随包分发，项目级技能放 .glaucous/skills/。
extensions/skills.py · assets/skills/

04上下文工程

长任务的物理极限是上下文窗口。四级压缩管线按「成本递增、侵入性递增」排列，逐级兜底。

📊 四级压缩管线

  • L0 输出截断：超长工具输出截断 + 全文落盘 outputs/，可 read_output 回取（信息零丢失）；
  • L1 本地裁剪：零模型开销，按轮次结构裁剪冗余派生消息；
  • L2 模型摘要：水位 85% 触发，语义压缩并保关键事实；
  • 预算优雅终止：最后防线，不崩会话。
context/budget.py · context/compactor.py

🎛 三档窗口与占用可视

  • /context 运行时切档：128K / 512K / 1M（最大 1M），压缩阈值与子任务预算自动跟随；
  • 状态栏实时占用环（绿/黄/红三档）；方案锚防压缩后任务丢失（压缩后仍可回读方案全文）。
commands.py · agent/state.py

05权限系统与安全兜底

「敢让它自动跑」的底气来自这里：权限判据不是操作吓不吓人，而是有没有兜底。

🚦 三级定级 × 授权策略

  • 操作定级 SAFE / WRITE / DANGEROUS（命令分类器 + 路径守卫）；
  • 授权策略 auto-approve / per-action / deep-review，审批卡支持「同意 / 同类型豁免 / 拒绝并回退」；
  • 全部决策写 audit.log 审计。
permission/classifier.py · approval.py · risk.py

🏖 Git 兜底区矩阵 v1.1 核心决策

  • 工作区是 Git 仓库 → 区内文件写 免审（快照可精确回退）、区内危险命令降级为可豁免；
  • 恒定守卫：.glaucous/ 写、区外写、push --force 永不放宽——快照兜不住的地方坚决拦；
  • 非 Git 工作区自动退回严格矩阵。
permission/workspace.py · tools/files.py

📸 Checkpoint 回退

  • 临时索引五步法打 Git 快照（捕获 untracked，不碰真实索引），保留最近 50 个；
  • /rollback 一键还原（变更清单确认卡 + 精确还原）；审批「拒绝」可联动自动回退；
  • 快照刻意排除 .glaucous/（运行态与审计防篡改）。
checkpoint/git_snapshots.py · commands.py

06Spec 流水线（大任务一等公民）

竞品调研结论：主流 coding agent 都没有内置的规格阶段。Glaucous 把 Spec 做成产品级一等公民——大方案与大任务的书面契约。

🔄 完整生命周期状态机

  • draft → reviewing → approved → executing → code_review → verified / archived，修订回环只增轮次号；
  • Spec 产物落盘 .glaucous/specs/，全程可追溯。
spec/store.py（状态机 + frontmatter）

🔁 双评审循环（各 ≤3 轮）

  • Spec 评审：子 agent 对照需求查一致性，阻塞项修完才放行；
  • 代码评审：执行后子 agent 对照 Spec 验收标准与 diff 查偏差；
  • 全自动模式下评审通过即跳过批准卡直接执行，不打扰用户。
spec/pipeline.py · tools/spec_tool.py

✅ 防跑偏四道闸

  • 任务消息内联「不越界」约束 → Spec 锚随时回读 → 代码评审对照 diff → 验收逐条核验（全 ✓ 且无 ✗ 才通过）。

07多 Agent 协作

🤖 spawn_agent 隔离派发

  • 子 agent 在独立上下文运行：自主探索、执行，中间过程不进主上下文；
  • 回传结构化报告（四段契约：结果摘要/修改清单/验证结果/风险遗留），≤1000 字，超限落盘 outputs/ 供回取；
  • 分工原则：评审用子 agent（隔离），执行用主 agent（可控）。
tools/interactive.py · agent/loop.py

🧩 为什么不做并行

  • v1 评审场景串行足够（父等报告）；并行需调度/合并/权限并发控制，复杂度与收益不匹配——已登记为 v2 增强。诚实的取舍也是设计能力。
