## 第一部分：2 分钟演示视频脚本

**叙事策略**：视频以「演示为主、讲解为辅」——用一次真实的 `/spec` 大任务全流程证明「高自主长任务」，中间穿插 10 秒级机制讲解点题三条主线；剪辑 + 加速允许，长等待（模型生成、测试运行）一律 4~8 倍速并打字幕标注。

**素材准备**（录制前）：
- 干净演示工作区：`/tmp/video-demo`（git init + 初始提交 + 埋一个带 bug 的 `src/calc.py`）；
- 终端主题统一、字号放大（录屏可读）；确认 `echo $GLAUCOUS_API_KEY` 不出现在画面（不执行 env 打印类命令）；
- 录屏工具：WSL 终端 + OBS/系统录屏，1080p 即可（2 分钟远低于 200MB）。

## 第二部分：1 分钟项目介绍（面试口述稿）

> 各位老师好，我的项目是 **Glaucous**——一个完全自研的编程智能体。它的设计宗旨是：**高自主地跑长任务，尽可能少打扰人**。围绕这个宗旨有三条主线：
>
> **第一，让长任务跑得动。** 大任务先走 Spec 流程：生成一份含任务清单和验收标准的书面规格，经评审子 agent 审查后逐项执行。评审放在独立子 agent 里做，中间过程不占主上下文，只回传千字以内的结构化报告——配合我自己实现的四级上下文压缩（输出截断、本地裁剪、模型摘要），长任务跑几十步上下文占用仍然很低。
>
> **第二，减少干扰的前提是需求明确。** Spec 入口强制先用交互式访谈澄清需求，用户确认「清楚」才动手；还支持 fork 会话，需求有疑虑时先在分支里讨论干净。
>
> **第三，敢放手是因为有兜底。** 每轮任务自动打 Git 快照，随时一键回退；审批卡支持「拒绝并回退」。权限矩阵按「有没有兜底」划分：有 checkpoint 兜底的区内操作尽量放开，区外、运行时目录、远端操作坚决拦住。
>
> 核心引擎——主循环、流式解析、终止条件、错误处理、工具执行——全部自研，没有使用任何 agent 框架，336 个测试全绿。谢谢。

（全文约 420 字，正常语速 55~60 秒）

## 第三部分：两者如何互补 + 面试预判问答

**互补关系**：视频回答「它真的能干活吗」（证据：真实任务全流程 + 回退高光），1 分钟介绍回答「你为什么这么设计」（逻辑：宗旨 → 三主线）；两者共用「三条主线」同一叙事骨架，评委看完视频听介绍时锚点完全对应。面试深入追问则以《实现详解》§七决策速查应对。

**高频追问预案**：

| 可能的问题 | 回答要点 |
|---|---|
| 为什么不用 LangChain 等框架？ | 赛事要求自研是一方面；更本质是框架的抽象与我要的「细粒度权限/上下文工程」冲突——比如工具派发要接审批管线、压缩要按轮次结构裁剪，自研才能逐层控制 |
| 上下文压缩为什么分四级？ | 成本递增、侵入性递增：L0 截断零成本保信息（落盘可回取）；L1 本地派生摘要零模型开销；L2 模型压缩有开销但保语义；预算耗尽优雅终止是最后防线。水位 70%/85% 分级触发，避免过早压缩损失近期上下文 |
| 子 agent 为什么只做串行？ | v1 的评审场景串行足够（父等报告）；并行需要调度/合并/权限并发控制，复杂度与当前收益不匹配，已在计划表登记为 v2 增强 |
| checkpoint 为什么不用 stash？ | `git stash create` 捕获不了 untracked 新增文件，「新增文件被移除」的回退验收点会落空；改用临时索引 write-tree 方案，不碰工作树和真实索引 |
| 权限为什么这么设计？ | 核心判据是「有无兜底」而非「操作吓人程度」：有快照兜底的区内写放开（否则长任务每步弹卡，高自主不成立）；区外/运行时目录/远端无兜底必须拦。`.glaucous/` 恒拦是因为快照刻意排除它且审计防篡改是底线 |
| 模型输出解析失败怎么办？ | 连续 3 次解析失败熔断终止本轮；终止前为悬空 tool_call 补推失败结果——不补的话历史序列非法，整个会话会被 API 400 永久报废 |
| 怎么保证实现不偏离 Spec？ | 四道：任务消息内联「不越界」约束、Spec 锚随时可回读、事后代码评审对照 diff 查越界、验收逐条核验 |
