# E5 改坏回退 · 执行说明（半自动）

本用例验证「改坏 → 恢复」的兜底能力差距。任务刻意设计为易改坏：
签名变更 + 删除旧测试，重构中途或完成后测试大概率红/结构破坏。

## v1.1 组步骤

1. `bash eval/run_case.sh e5-rollback`（任务下达后等待执行）；
2. 执行中或执行后确认「改坏」状态：`cd /tmp/eval-e5-rollback-* && python3 -m pytest tests/ -q`（预期红或收集失败）；
3. 在同一会话执行 `/rollback` → 选择任务入口快照 → 确认变更清单 → 文件还原；
4. 运行 `bash eval/cases/e5-rollback/check.sh /tmp/eval-e5-rollback-<时间戳>`，预期 `PASS`；
5. 记录：改坏到恢复的**操作次数与耗时**（预期：1 条命令 + 1 次确认）。

## v1.0 组步骤（对照组）

1. 同上 1~2（v1.0 无 checkpoint，任务下达即为普通任务）；
2. 确认改坏后：v1.0 **无任何内置回退命令**，需评测者手工恢复
   （`git checkout .` + `git clean -fd` 或逐文件处理）——如实记录步骤数与耗时；
3. 运行同一 `check.sh`，恢复手段不限（判定只看结果）；
4. 记录：操作次数、耗时、是否依赖评测者具备 git 知识。

## 对比叙事（写进报告）

- v1.1：agent 内置兜底，任何用户一条命令恢复，不依赖用户 git 水平；
- v1.0：无兜底，恢复成本转嫁给用户；若用户在真实项目中未及时提交，损失不可逆；
- 进阶：补充演示「拒绝并回退」（per-action 策略下中途拒绝同时回退，见评测方案 E6）。
