# E6 拒绝联动回退 · 执行说明（半自动）

验证 per-action 策略下的「拒绝并回退」联动：用户在写审批卡上选择拒绝时，
已执行的写操作应随决策一并回退（文件回到任务前），且审计留痕。

## v1.1 组步骤

1. `bash eval/run_case.sh e6-reject-rollback`（任务含多处写操作：
   修 bug、建测试、加配置——首卡即会出现）；
2. 在**首个写审批卡**选择「拒绝并回退」（v1.1 特有选项）；
3. 运行 `bash eval/cases/e6-reject-rollback/check.sh /tmp/eval-e6-reject-rollback-<时间戳>`，预期 `PASS`；
4. 记录：拒绝时的上下文（第几张卡、已完成几步写操作）与回退耗时。

## v1.0 组步骤（对照组）

1. 同上运行；v1.0 拒绝仅终止当前工具调用（无联动回退选项）；
2. 若 agent 在拒绝前已完成部分写操作，工作区残留脏状态——
   运行同一 `check.sh` 预期 `FAIL: 文件未回到任务前`，如实记录；
3. 手工 `git checkout . && git clean -fd` 恢复后记录操作步骤数。

## 对比叙事（写进报告）

- v1.1：拒绝即回退，用户决策与工作区状态原子一致，审计可查；
- v1.0：拒绝只是踩刹车，已产生的副作用留给用户自己收拾；
- 判据客观：git 工作树比对 + 审计日志 grep，两条件缺一不可。
